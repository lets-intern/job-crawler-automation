# Tasks: 본문 채우기 - Push 2

> PRD: `.claude/tasks/done/fill-body/prd-fill-body.md`
> Push 범위: 본문을 못 얻은 공고를 저장하지 않고, 마감·중복은 상세를 열지 않는다 (실행)
> 상태: 완료

## 배경 (PRD 를 안 봐도 되도록)

지금 실행은 상세에 못 가도 목록에서 읽은 값만 넣고 성공으로 넘긴다. 그렇게 86건이 본문 없이
쌓였다. 이 Push 가 그 동작을 바꾼다.

두 가지를 한다.

1. **본문이 없으면 `raw_jobs` 에 넣지 않는다.** 실행 기록에 실패로 남긴다 (Push 1 이 만든 자리)
2. **마감이 지났거나 이미 저장한 공고는 상세를 열지 않는다.** 건너뛴 수를 따로 센다

## 관련 파일

- `app/crawler/runner.py:361` - `_crawl()` 이 목록을 읽는다
- `app/crawler/runner.py:405` - `_collect()` 가 항목 하나를 상세까지 가져와 적재한다
- `app/crawler/runner.py:491` - `_record()` 가 목록 값과 상세 값을 합쳐 `raw_jobs` 행을 만든다
- `app/crawler/runner.py:517` - `_is_known()` 이 이미 아는 공고인지 본다
- `app/crawler/collect.py:145` - `open_collectors()` 가 목록·상세 수집기를 고른다
- `app/crawler/parser.py` - `ListItem` 에 `detail_absent` 가 있다
- `app/normalize/rules.py` - 날짜 규칙이 있다. 마감 판정에 이것을 쓴다
- `app/api/ui.py` - `display_zone()`. 날짜 비교는 이 시간대로 한다

    - [x] 2.1 본문이 비면 적재하지 않는다

          도달 실패는 경로 문제, 본문 없음은 매핑·셀렉터 문제라 고치는 곳이 다르다
        - **목록에서 읽은 제목을 실패에 같이 싣는다.** 주소만으로는 어느 공고인지 모른다
        - [x] 2.1.V 검증: 픽스처 기반 pytest — 본문이 빈 상세를 주면 `raw_jobs` 행이 늘지 않고

        - 매칭 0건은 성공이 아니다. 이미 그렇게 되어 있으니 사유 이름만 정확히 한다
        - [x] 2.2.V 검증: 픽스처 기반 pytest — 빈 목록에서 `list_empty` 가 나오는지
    - [x] 2.3 마감이 지난 항목은 상세를 열지 않는다
        - 목록에서 읽은 마감일로 판정한다. `app/normalize/rules.py` 의 날짜 규칙을 쓴다.

        - **읽지 못한 날짜는 진행 중으로 본다.** 못 읽은 것과 지난 것은 다르다. 날짜 형식이

        - 마감일이 없는 것(상시채용)도 진행 중이다
        - 오늘 마감인 공고는 진행 중이다. 비교는 `app/api/ui.py` 의 `display_zone()` 기준
          날짜로 한다 — UTC 로 비교하면 한국 시각 오전에 하루 일찍 마감된 것으로 보인다
        - [x] 2.3.V 검증: 픽스처 기반 pytest — 지난 날짜·오늘·미래·빈 값·못 읽는 문자열·
              `상시채용` 각각의 판정
    - [x] 2.4 이미 저장한 공고는 상세를 열지 않는다
