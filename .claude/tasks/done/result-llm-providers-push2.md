## 저장 모양

일곱 줄이라 `app_settings` 로 충분하다. 새 표도 마이그레이션도 만들지 않았다.

| 행 | 몇 개 | 예 |
|---|---|---|
| `llm_key_<제공자>` | 4 | `llm_key_qwen` |
| `llm_provider_<기능>` | 3 | `llm_provider_classify` -> `qwen` |
| `llm_model_<기능>` | 3 | `llm_model_classify` -> `qwen3.8-flash` |

**모델이 제공자가 아니라 기능에 붙는다.** 같은 제공자를 쓰면서 셀렉터 생성에 비싼 모델을,
분류에 싼 모델을 둘 수 있다.

읽기는 `settings_for(conn, feature, settings)` 하나로 나간다. 덮어쓴 `Settings` 사본을
돌려주므로 부르는 쪽이 이미 넘기고 있던 `settings=` 자리에 그대로 들어간다 — **호출 자리의
서명이 하나도 바뀌지 않았다.** 기능마다 사본이 따로 나오는 것이 "같은 제공자, 다른 모델" 을
가능하게 하는 자리다.

### 2.6 을 어떻게 눌렀나

화면에서 `...WXYZ` 로 끝나는 키를 저장 -> 스냅샷 내려받기(102400바이트) -> 그 파일을

## 하다가 늘어난 것 둘

task 파일에 2.8·2.9 로 적고 실행했다.

### 2.8 — 가져오기가 키를 옮기지 않고 있었다

2.5 의 문구("가져오기로 다른 서버에 올리면 키도 같이 옮겨진다")를 쓰기 전에 눌러 보니
**옮겨지지 않았다.** 내보낸 파일 안에는 `llm_key_qwen` 이 있는데 가져오기 뒤 받는 쪽에는
없다. `app/api/import_data.py` 가 옮기는 것은 크롤러·워크플로우·규칙·공고·보정 다섯뿐이고
`app_settings` 는 그 목록에 없었다.

PRD 3장이 그렇게 적고 2.6 이 그것을 검증하라고 하므로 코드를 문서에 맞췄다. 좁게 했다 —
옮기는 것은 `app/llm/settings.py` 의 행뿐이고, 이미 값이 있는 항목은 덮지 않는다. 알림 주소와
동시 실행 상한은 따라오지 않는다. `app_settings` 를 통째로 옮기면 이 서버의 운영 설정이 남의
파일 하나로 바뀐다.

**이것은 task 파일이 이름으로 지목하지 않은 파일을 고친 것이다.** 2.6 이 요구하는 결과가
그것 없이는 나오지 않아서 했다. 되돌리려면 `2d41b92` 하나만 지우면 된다.

### 2.9 — 저장소만 있고 읽는 자리가 없었다

2.1 은 값을 담는 곳을 만들었지만, 그것을 읽는 코드가 없으면 화면은 값을 받아 두기만 하는
상자다. PRD 3번과 2.7 이 그것을 검증하라고 하므로 세 자리에 끼웠다 — 분류는 실행마다,
셀렉터 생성과 AI 수정은 요청마다 다시 읽는다.

**저장소를 몰래 열지 않았다.** 연결은 부르는 쪽이 준다. LLM 계층이 스스로 DB 를 열면 테스트가
개발 기계의 운영 DB 를 읽게 되고, `Settings(classify_provider=...)` 로 고정한 테스트가 그
기계에 무엇이 저장돼 있느냐에 따라 흔들린다.

대가는 `get_generator()` 가 연결을 받게 된 것이다. 직접 부르던 테스트 6곳이
`get_generator(None)` 이 됐다 — 연결 없이 부르면 환경변수 그대로다.

## 구현하면서 정한 것

**네 자리 키도 가린다.** task 는 "네 자리보다 짧은 값은 전부 가린다" 고 적었는데, 네 자리
키의 끝 네 자리는 그 키 전체다. 다섯 자 이상일 때만 끝 네 자리를 보여준다.

**빈 값을 저장하면 그 키를 지운다.** 지우는 길이 없으면 잘못 넣은 키를 화면에서 뺄 방법이
없다. 지우면 환경변수 값으로 돌아간다.

**모델을 비우고 저장하면 그 행을 지운다.** 지금 값을 베껴 넣어 두면 배포가 모델을 올려도 그
기능만 옛 모델에 남는다.

**저장할 때 스키마 강제 여부도 본다.** 별칭(`qwen-plus` 등)을 분류에 지정하면 저장 자체를
거절한다. `app/llm/providers.py` 의 `resolve()` 를 그대로 부르는 한 줄이고, 저장은 됐는데
첫 호출에서 서는 조합을 만들지 않는다.

**마스킹을 2.1 커밋에 같이 넣었다.** 저장소가 키 전체를 내보내는 상태로 한 커밋이라도 남으면
그 사이에 붙는 화면이 그것을 그대로 그린다. 2.2 의 커밋은 네 경우를 잠그는 테스트다.

## 발견했지만 하지 않은 것

### compose 가 새 환경변수를 컨테이너에 넘기지 않는다 (Push 1 에서 이어짐)

`docker-compose.yml` 과 `docker-compose.coolify.yml` 에 Push 1 이 만든 환경변수 열 개가 없다.
**이번 Push 범위가 아니라 그대로 뒀고, 아직 열려 있다.**

다만 급한 정도는 내려갔다. 이제 키와 제공자를 화면에서 넣을 수 있고 그 값이 DB 에 남으므로,
컨테이너에 환경변수가 없어도 운영자가 화면에서 채우면 돈다. compose 줄은 "배포가 기본값을
심어 두는" 편의로 남는다.

### `llm_calls` 가 운영 DB 에 있다

`.claude/rules/llm.md` 는 호출 기록을 "로그 DB, 운영 DB 가 아니라" 에 쓰라고 적는데,
`record_call()` 은 요청 연결을 그대로 받아 같은 파일에 쓴다. 2.7 을 확인하면서 눈에 띈 것이고
Push 1 이나 그 이전부터 그랬다. **이번 Push 에서 만든 것이 아니라 손대지 않았다.**

### `tests/test_llm_feature_provider.py` 에 mypy 오류가 하나 있다

**남의 파일이라 고치지 않았다.** 한 줄이다.
