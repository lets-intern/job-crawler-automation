## 검증의 한계

**브라우저에서 실행하지 못했다.** 실행 환경에 브라우저가 없어, HTMX 가 보낼 요청(메서드,
`HX-Request` 헤더, 폼 인코딩)을 그대로 재현해 조각 응답을 확인하고 페이지의 `hx-get`·`hx-target`·
`hx-swap` 속성이 그 조각의 id 를 가리키는지 대조하는 방식으로 검증했다.

코디네이터도 브라우저 확장이 연결되지 않아 확인하지 못했다. 자바스크립트가 실제로 실행되는
경로는 아직 사람 눈으로 확인되지 않은 상태다. 컨테이너를 재빌드해 8000 에 띄워 뒀다.

## 이슈 및 특이사항

- `pyproject.toml` 에 `python-multipart` 를 추가했다. FastAPI 폼 파싱에 필요하다
- `app/crawler/runner.py` 의 `_consecutive_failures` 를 `consecutive_failures` 로 공개했다.
  임계치 표시가 자동 중지와 같은 값을 봐야 해서다. 이름만 바뀌었고 동작은 그대로다
- 검증은 별도 DB 와 로컬 픽스처 서버로 했고 외부 사이트 요청은 Gemini 생성 1회를 빼면 없다

## 남은 일 (이 Push 범위 밖)

- **승격 경로가 화면에 없다.** 크롤러 생성과 테스트까지는 화면에서 되지만 워크플로우 승격은
  `POST /api/workflows` API 로만 가능하다. 화면만 쓰는 운영자는 파이프라인을 끝까지 못 간다
- `normalized_jobs.company` 가 항상 NULL 이라 6.6 의 회사 필터는 값이 있어야 의미가 있다.
  Push 7 이 이것을 해결한다

  그 실행에서만 보여주는 선까지 했다
