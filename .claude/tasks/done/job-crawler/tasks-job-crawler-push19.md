## 왜 필요한가

배포된 서버는 빈 DB 로 시작한다. 로컬에서 쌓은 데이터를 옮기려면 지금은 SSH 로 파일을 올리고
`docker cp` 를 쳐야 하는데, 운영자가 화면만 쓰는 이 서비스에서 그것은 길이 아니다.

2026-08-23 에 실제로 막혔다. Coolify 로 배포하면서 로컬 138건을 옮길 방법이 화면에 없었다.

## 덮어쓰지 않는다. 더한다

**`raw_jobs` 는 append-only 다** (`.claude/rules/data-safety.md`). 올린 파일의 내용을 기존 행에
덮어쓰지 않는다. 없는 것만 넣는다.

중복은 `content_hash` 로 가른다. 같은 해시가 이미 있으면 건너뛴다. 그 판정은 이미
`app/crawler/hashing.py` 가 하는 일이고 여기서 다시 만들지 않는다.

## 정규화 값은 가져오지 않는다

올린 파일의 `normalized_jobs` 를 복사하지 않는다. **가져온 `raw_jobs` 를 이 서버의 규칙으로
다시 정규화한다.**

이유는 규칙이 서버마다 다를 수 있어서다. 저쪽 규칙이 만든 값을 그대로 들여오면, 이 서버의
`normalization_rules` 와 `normalized_jobs` 가 어긋난 채로 남는다. 재정규화를 돌리면 그때
값이 바뀌는데 왜 바뀌었는지 아무도 모른다.

`raw_jobs` 만 진실이고 나머지는 그것에서 만들어진다 — 그 방향을 여기서도 지킨다.

## delivered_at 은 가져오지 않는다

올린 파일에서 이미 전달된 행이라도, **이 서버의 소비 측은 그것을 받은 적이 없다.**
`delivered_at` 을 들여오면 소비 측이 영영 못 받는 공고가 생긴다.

가져온 행은 전부 미전달로 들어간다. `delivered_at` 을 쓰는 것은 제공 API 하나뿐이라는 규칙도
그대로다.

## 올라온 파일은 신뢰하지 않는다

임의의 SQLite 파일이 들어온다. 손대기 전에 확인한다.

- SQLite 파일인가
- 우리 스키마인가. 기대하는 테이블과 컬럼이 있는가
- 마이그레이션 버전이 이 서버보다 앞서지 않는가. 앞선 파일은 거절한다 — 모르는 컬럼을 읽을 수 없다
- 크기 상한을 둔다

전부 한 트랜잭션이다. 중간에 틀어지면 아무것도 들어가지 않는다.
