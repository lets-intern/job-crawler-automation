## 무엇이 불편한가

2026-08-22 브라우저 QA 에서 전 구간이 동작하는 것은 확인됐다. 남은 것은 쓰기 불편한 부분이다.

**검수 화면의 셀 편집이 좁다.** 표 안의 작은 입력에서 본문과 자격요건을 고친다. 본문은 수백 자고
자격요건은 여러 줄인데 표 셀 폭에 갇혀 있다.

**조회 화면의 상세가 아래로 밀린다.** "상세" 를 누르면 표 아래 영역이 채워져 스크롤해야 보인다.
목록과 상세를 오가며 비교하기 어렵다.

**워크플로우 표가 넘친다.** Push 15 가 조작을 별도 줄로 내려 1440px 에서 1225px 까지 줄였지만
`임계치` 열이 아직 가로 스크롤 안쪽이다. 열이 열 개다.

## 모달을 어떻게 만드는가

**빌드 단계도 SPA 프레임워크도 넣지 않는다** (`.claude/rules/core.md`). 브라우저 기본
`<dialog>` 와 HTMX 로 만든다. 여는 것과 닫는 것에 필요한 최소한의 인라인 스크립트는 허용한다 —
그것은 프레임워크가 아니다.

지켜야 할 것.

- `Esc` 로 닫힌다. `<dialog>` 가 기본으로 해 준다
- 열릴 때 포커스가 모달 안으로 가고, 닫히면 열었던 버튼으로 돌아온다
- 모달 안에서 저장하면 **뒤에 있는 표의 그 행도 함께 갱신된다.** OOB 교체를 쓴다.
  닫았더니 표에 옛 값이 남아 있으면 사용자는 저장이 안 된 줄 안다
- 표 전체를 다시 그리지 않는다. Push 6 이 확인한 부분 갱신을 깨지 않는다
- 모달 안이 길면 모달 안에서 스크롤한다. 페이지가 스크롤되지 않는다

## 작업

- [x] 16.0 모달과 워크플로우 정리 (Push 범위)

    - [x] 16.1 검수 셀을 모달에서 고친다
        - 셀을 누르면 모달이 열리고 그 안에서 값을 고친다. 본문·자격요건은 넓은 여러 줄 입력이다
        - 모달 안에 규칙이 만든 값을 함께 보여준다. 무엇을 바꾸는 것인지 알아야 고칠 수 있다
        - 이미 전달된 행이면 모달 안에서 알린다 — 고쳐도 소비 측이 가진 값은 바뀌지 않는다
        - 저장하면 모달이 닫히고 표의 그 셀이 갱신된다. 보정 삭제도 모달 안에서 된다
        - 표에서 바로 고치는 지금 방식을 없앨지 모달로 합칠지는 만드는 쪽이 정한다.
          두 경로가 남아 헷갈리지만 않으면 된다
        - [x] 16.1.V 검증: 로컬에서 본문 셀을 모달로 열어 고치고 저장한 뒤, 모달이 닫히고 표의 그 셀만
          바뀌는지, `job_field_overrides` 에 행이 생기는지, 새로고침 후에도 유지되는지 확인.
          `Esc` 로 닫히고 포커스가 돌아오는지 확인

    - [x] 16.2 조회 상세를 모달로 연다
        - 표의 "상세" 를 누르면 모달에서 전체 값을 본다. 본문과 자격요건이 잘리지 않는다
        - 원문 링크를 모달 안에 둔다
        - 읽기 전용이다. 고치는 것은 검수 화면의 일이다. 두 화면의 역할을 섞지 않는다
        - [x] 16.2.V 검증: 로컬에서 상세를 열어 본문 전체가 보이는지, 모달 안에서 스크롤되고 페이지는
          움직이지 않는지, 닫은 뒤 표의 필터와 검색어가 그대로인지 확인

    - [x] 16.3 워크플로우 화면 정리
        - 열 열 개를 한 표에 밀어 넣지 않는다. 워크플로우 하나를 카드나 두 줄 구성으로 바꾸는 것을 포함해
          만드는 쪽이 정한다. 판정 기준은 **1280px 에서 가로 스크롤 없이 모든 값과 조작이 보이는지**다
        - 상태(`실행 중`/`중지됨`), 최근 결과, 누적 성공·실패, 임계치가 한눈에 들어와야 한다
        - 실패가 쌓인 워크플로우가 눈에 띄어야 한다. 색과 굵기로 구분하되 단어를 지우지 않는다
        - 주기 저장·중지·재개·지금 1회 실행은 그대로 그 워크플로우 자리만 갱신한다
        - [x] 16.3.V 검증: 1280px 과 1440px 에서 가로 스크롤이 없는지 문서 폭으로 확인.
          중지·재개·주기 저장·1회 실행을 눌러 그 워크플로우만 갱신되는지 확인

    - [x] 16.4 실행이 화면을 붙잡지 않게
        - QA 에서 "지금 1회 실행" 이 응답까지 2분 가까이 걸려 브라우저 클릭이 타임아웃 났다
        - 실행을 시작만 하고 바로 돌려준 뒤, 그 줄이 상태를 폴링해 끝나면 결과로 바뀌게 한다
        - 실행 중에는 그 줄에 진행 중임을 적고 버튼을 잠근다. 끝나면 폴링을 멈춘다
        - 이미 실행 중이면 새로 시작하지 않는 지금 동작을 유지한다
        - [x] 16.4.V 검증: 로컬에서 1회 실행을 누른 직후 응답이 바로 오는지, 실행 중 표시가 뜨고
          끝나면 최근 결과가 갱신되며 폴링이 멈추는지 확인. 실사이트는 현대자동차 한 번만 쓴다
