## 배경

화면이 기능별로 하나씩 붙으면서 같은 것을 화면마다 다르게 그리고 있다. 단추 모양, 표 머리,
실패 표시, 빈 상태, 확인 창이 화면마다 조금씩 다르다.

이 서비스에는 사용자가 없다. 운영자 한 사람이 셀렉터를 등록하고, 실행을 들여다보고, 규칙을
고친다 (`.claude/rules/core.md`). 그러니 목표는 예쁨이 아니라 **한 화면에서 배운 것이 다음
화면에서 그대로 통하는 것**이다.

## 관련 파일

- `app/templates/base.html` (343줄) - 레이아웃과 공통 클래스가 여기 모인다
- `app/templates/pages/` - crawlers, tests, workflows, rules, settings, login
- `app/templates/fragments/` - HTMX 가 갈아 끼우는 조각들

**`pages/jobs.html`, `pages/review.html`, `fragments/job_*`, `fragments/review_*` 는 건드리지
않는다.** Push 27 이 그 두 화면을 쓴다.

## 28.1 에서 찾은 것

여섯 화면(`/`, `/tests`, `/workflows`, `/rules`, `/settings`, `/login`)을 1440px 와 420px 로
띄워 보고 적는다. 확인 방법은 로컬 8080 인스턴스와 DB 사본이다 (포트 8000 은 건드리지 않았다).

### 실패 표시

| 자리 | 지금 모양 |
|---|---|
| `fragments/error.html` | 붉은 상자. `실패 — 사유` / 내용 / `다음:` |
| `fragments/crawler_result.html` | 상자 없음. `<h3>실패</h3>` + `<dl>` 로 사유·내용·다음 |
| `fragments/test_result.html` | 상자 없음. `<h3>실행할 수 없다</h3>` + `<dl>` |
| `fragments/test_repair.html` | 상자 없음. `<h3>고치지 못했다</h3>` + `<dl>` |
| `fragments/rule_list.html` | 붉은 상자. `저장하지 못했다 — 사유:` + 다음 |
| `fragments/settings_form.html` | 붉은 상자. `저장하지 못했다:` 한 줄. 사유·다음 없음 |
| `fragments/renormalize.html` | 붉은 상자. `시작하지 못했다:` 한 줄. 사유·다음 없음 |
| `fragments/rule_preview.html` | 붉은 상자. `규칙을 읽지 못했다`. 다음 없음 |
| `fragments/import_result.html` | 붉은 상자. `거절 —`, 사유는 다음 줄 `<code>`. 다음 없음 |

같은 클래스 문자열이 열두 자리에 복사돼 있고 여백만 두 가지(`px-4 py-3`, `px-3 py-2`)다.
가장 흔한 실패인 셀렉터 생성 실패가 붉은 상자를 쓰지 않는 쪽이라, 화면에서 성공과 구별되지
않는다. `NEXT_STEPS` 문구가 붙는 자리와 안 붙는 자리가 섞여 있다.

### 대기 표시

- 누른 단추가 잠기면 **글자가 사라진다.** `base.html` 의 `button[disabled]` 가 `hover:bg-white`
  를 걸어, 포인터가 올라가 있는 채로 잠긴 제출 단추는 흰 바탕에 흰 글자가 된다. 누른 직후
  포인터는 늘 그 단추 위에 있으므로 항상 이렇게 된다. "누른 건지 안 누른 건지 확인이 안 된다"
  가 이 자리다
- 대기 문구는 본문과 같은 크기·색이라 상태로 읽히지 않는다
- 규칙 미리보기에는 대기 문구가 아예 없다

### 표

- `/tests` 의 `동작` 열이 1440px 에서 잘린다. 화면의 주된 단추인 `테스트 실행` 이 가로
  스크롤 밖으로 나간다
- `/rules` 는 `저장`·`활성 토글`·`삭제` 가 각각 한 열씩 세 열이고, 1440px 에서 `삭제` 열이
  잘린다. 다른 화면은 `동작` 한 열에 모아 둔다
- `/rules` 빈 상태 행의 `colspan` 이 9 인데 열은 10 이다
- `/` 의 `렌더` 열은 `playwright` 를 그대로 쓰고, `/tests` 의 `저장 모드` 열은 `렌더
  (playwright)` 로 쓴다. 같은 값이 화면마다 다른 말이다
- `항목 미리보기` 의 값이 빈 칸은 아무 글자 없이 비어 있다. 빈 칸은 반대 뜻으로 읽힌다
  (`.claude/rules/writing.md`)

### 단추

- 무게가 `type="submit"` 인지로 갈린다. `/` 목록의 모드 토글(`렌더로`)은 진한 단추고 같은
  칸의 `셀렉터 편집` 은 테두리 단추다. 행에서 가장 덜 중요한 것이 가장 진하다
- `/settings` 의 `스냅샷 내려받기` 는 `<a>` 에 클래스를 직접 붙여 다른 진한 단추보다 크다
- `/rules` 미리보기의 `미리보기` 단추도 클래스를 직접 들고 있어 모서리와 크기가 다르다

### 좁은 화면 (420px)

- 페이지 본문이 가로로 밀리는 화면은 없다. 표는 제 상자 안에서 스크롤한다
- `/workflows` 의 `임계치 저장` 단추가 한 줄에 한 글자씩 세로로 쌓인다. `button` 에
  줄바꿈 금지가 없다

### 판정 낱말

- 판정하지 않은 필드를 `/` 의 생성·수정 표는 `건너뜀`, `/tests` 의 필드별 판정 표는
  `해당 없음` 이라고 쓴다. `app/api/ui_tests.py` 의 주석도 둘을 같은 것으로 적고 있다

### 그 밖에

- 입력창 글꼴이 전부 고정폭이다. 셀렉터 JSON 은 맞고, 힌트·메모처럼 문장을 적는 칸까지
  고정폭이라 읽기 나쁘다
- `/settings` 의 첫 구역만 `h3` 제목이 없다
- `/settings` 의 `올릴 파일 (`jobs.db`)` 라벨에 마크다운 백틱이 그대로 나온다
- `/rules` 의 `규칙 추가` 폼은 `<p>` 안에서 `</label>` 이 짝 없이 닫히는 자리가 있다

### 고칠 것

1. 실패 상자 하나로 모으고, 사유·내용·다음을 늘 같이 적는다 (`NEXT_STEPS` 그대로)
2. 잠긴 단추의 글자가 사라지는 것을 고치고, 대기 문구를 한 모양으로 만든다
3. 빈 상태·빈 칸을 글자로 채운다
4. `/tests`, `/rules` 의 표를 1440px 에서 단추가 보이게 정리한다
5. `button` 에 줄바꿈 금지를 준다 (420px)
6. 판정하지 않은 필드를 한 낱말(`건너뜀`)로 통일한다
7. 단추 무게를 `주됨/보통/위험` 으로 갈라 `base.html` 에서 정한다
8. 문장을 적는 입력칸의 고정폭 글꼴을 푼다
9. `/settings` 첫 구역 제목, 백틱, `/rules` 폼의 짝 없는 태그를 고친다

### 그냥 두는 것

- 워크플로우 화면의 카드 구조. 표로 되돌리지 않는다 (`fragments/workflow_card.html` 이
  이유를 적어 두었다)
- 회사명 빈 값의 `안 적음`. `없음` 과 뜻이 다르다 — 사이트에 없는 것이 아니라 운영자가
  안 적은 것이다
- `상태` 열의 `승격됨 (promoted)` 처럼 단어와 저장값을 같이 적는 방식. 이미 세 화면이 같다
- 로그인 화면이 `base.html` 을 상속하지 않는 것. 이유가 파일에 적혀 있다
- 워크플로우의 `실행 중` 배지 낱말. 재정규화의 `실행 중` 과 뜻이 다르지만, 배지를 바꾸면
  운영자가 익힌 낱말이 바뀐다. 이 Push 에서는 손대지 않는다
- 색 테마, 여백 값 자체, 글자 크기 규모
