## 무엇이 불편한가

AI 수정이 크롤러 등록 화면에만 있다. 그런데 실패는 **주기 실행에서** 난다. 지금은 실패를
발견하면 등록 화면으로 돌아가 다시 생성해야 하고, 생성은 실패 필드만 고치는 것이 아니라
전부 다시 만든다.

그리고 모델이 못 고치는 경우가 있다. 2026-08-23 에 LG 의 `list.link` 가 그랬다 — 항목 안에
`a` 태그가 없어 모델이 찾을 것이 없었다. 사람은 브라우저에서 그 자리를 볼 수 있는데, 그것을
모델에게 전달할 길이 없었다.

운영자가 원하는 흐름은 이것이다.

```
주기 실행 실패 → 테스트 실행에서 다시 돌림 → 실패 필드 확인
              → AI 수정 + 힌트 전달 → 저장 → 다시 테스트
```

## 힌트를 어떻게 다루는가

운영자가 F12 로 딴 `Copy selector` 경로가 힌트로 들어온다. 실제 예다.

```
#root > div > div > main > div > div.MuiBox-root.css-jj9lbc > div > div >
div.MuiBox-root.css-1jelp97 > div:nth-child(2) > div
```

**그대로 쓰지 않는다.** `css-jj9lbc` 는 빌드마다 바뀌는 자동 생성 클래스고, `div:nth-child(2)`
는 항목이 하나 늘면 어긋난다. 그것을 저장하면 다음 배포에 깨지는 셀렉터를 심는 것이다.

이 경로는 **어디를 보라는 위치 정보**로 쓴다. 모델에게 그 자리 근처에서 안정적인 셀렉터를
찾게 한다 — 의미 있는 클래스, `data-` 속성, 태그 구조 같은 것이다. 그런 것이 없으면 그때는
받은 경로를 써도 된다. 다만 왜 그것밖에 없는지 결과에 적는다.

힌트는 자유 입력이라 셀렉터가 아닐 수도 있다. "마감일은 목록 두 번째 줄에 있다" 같은 문장도
그대로 받는다. 모델에게는 둘 다 그냥 사람이 준 단서다.

## 하면서 갈린 것

**AI 수정 수단을 늘 보이게 했다.** 처음에는 실패한 필드가 있을 때만 냈는데, 실행이 성공이어도
잡히는 값이 틀릴 수 있고 그때 고칠 길이 없으면 운영자가 화면에서 막힌다. 두 화면 모두 판정
결과가 있으면 버튼과 힌트칸이 남고, 고칠 것이 없으면 그 사실과 다음 수를 그 자리에 적는다.
편집기만 열었을 때는 판정한 적이 없으므로 내밀지 않는다.

**힌트가 있으면 대상이 넓어진다.** 실패한 필드로만 대상을 두면, LG 처럼 `list.link` 가 늘
실패인 사이트에서는 다른 필드를 영영 힌트로 고칠 수 없다. 힌트가 들어오면 판정된 필드
전부가 대상이 되고, 잘 되는 필드에는 실패 사유 대신 지금 몇 건을 잡고 있는지를 적는다.
`건너뜀` 은 어느 쪽에서도 대상이 아니다.

**목록 전용 크롤러의 상세 필드는 실패가 아니다.** LG 실행에서 `detail.body` 가 `실패` 로
떴는데, LG 는 상세 페이지를 아예 열지 않는 크롤러라 채워질 수 없는 자리였다. `해당 없음` 과
사유로 바꿨다 (`app/api/ui_tests.py`).

건드리지 않았다.
