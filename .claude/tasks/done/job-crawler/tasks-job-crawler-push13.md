## 배경

정적으로 되는 것은 롯데뿐이고 삼성은 확인이 필요하다. **대상 사이트 대부분이 정적으로 안 된다.**

사용자 판단은 "Playwright 가 둘 다 되니 정적도 그것으로 처리하라" 다.

## 결정이 한 번 바뀌었다 (2026-08-22)

기본값을 렌더로 올렸다가(fa4ecfc) 되돌렸다(dc62fe6). 사용자 판단이 "정적은 우선은 유지하자"
로 바뀌었다. 기본값은 `static` 이고, 렌더는 테스트 실행 화면에서 확인한 뒤 사이트별로 올린다.

비용이 그 판단의 근거다.

| 항목 | 정적 | 렌더 |
|---|---|---|
| 실행당 메모리 | 사실상 0 | 브라우저 인스턴스당 150~300MB |
| 동시 실행 3일 때 최악 | 수십 MB | 900MB |
| 한 페이지 소요 | 수백 ms | 수 초 |

정적 경로는 지우지 않는다. 롯데처럼 정적으로 되는 사이트까지 브라우저를 띄우면 그만큼이 그냥
나가고, 코드를 지우면 되돌릴 때 다시 짜야 한다.

`.claude/rules/crawling.md` 와 `.claude/docs/architecture.md` 는 정적 우선을 그대로 두되,
측정된 6개 중 4개가 JS 렌더라는 사실과 어느 쪽으로 옮기든 테스트 실행으로 증명한다는 점을
반영했다.

## 남은 것

- 셀렉터 생성 프롬프트는 아직 "상세 페이지가 없다" 를 모른다. 상세 URL 없이 생성하면 모델이
  상세 셀렉터를 추측해서 낸다. 저장되긴 하지만 확인되지 않은 값이라 화면에 `건너뜀` 으로 나온다.
  프롬프트에 목록 전용 분기를 두는 것은 `app/selector/` 소유자의 일이다
