# [확장] AI 검수 기능 PRD

> 본 문서는 `job-crawler-prd.md`(채용공고 크롤링 자동화 서비스)의 확장 기능이다. 기본 크롤링/정규화/적재 파이프라인이 구축된 이후 적용을 전제로 한다.

## 1. 개요

크롤링·정규화 과정에서 셀렉터 오작동, 텍스트 깨짐, 필드 누락, 유사/중복 공고 등이 발생할 수 있다. 사람이 모든 데이터를 일일이 확인하기는 비효율적이므로, LLM을 이용해 정규화된 데이터를 자동 검수하고 이상 있는 건만 사람이 확인하도록 하는 기능을 추가한다.

## 2. 목표 / 비목표

**목표**
- 어드민(데이터 테이블) 화면에서 "AI 검수" 버튼으로 정규화된 데이터를 LLM에 보내 이상 유무를 판정
- 검수 결과를 데이터에 상태값으로 기록해, 사람은 플래그된 건만 골라서 확인
- 배치 처리로 LLM 호출 비용 최소화

**비목표**
- 검수 결과에 따른 자동 수정/자동 삭제 (1차는 판정 + 표시까지만, 실제 수정은 사람이)
- 실시간(정규화 즉시) 자동 검수 — 1차는 수동 트리거 버튼 기반

## 3. 사용자 플로우

1. 데이터 테이블 화면에서 검수할 대상 선택
   - 개별 행 체크박스 선택, 또는 "검수 안 된 데이터 전체" 일괄 선택
2. "AI 검수" 버튼 클릭
3. 백엔드가 선택된 데이터를 배치(예: 20~50건 단위)로 묶어 LLM에 전달
4. LLM이 각 건에 대해 판정 결과(JSON) 반환 → DB에 검수 상태/사유 저장
5. 테이블에서 검수 상태 컬럼(미검수/정상/플래그됨) 확인, 플래그된 건만 필터링해서 사람이 최종 확인
6. 사람이 확인 후 필요 시 직접 데이터 수정 (기존 데이터 편집 기능 재사용)

## 4. 기능 명세

### 4.1 검수 트리거
- 데이터 테이블에서 개별/다중 선택 후 "AI 검수" 버튼
- "검수 안 된 데이터 전체" 일괄 검수 버튼 (별도)
- 검수 진행 중에는 진행률 표시 (배치 단위 처리이므로 몇 건 중 몇 건 처리됐는지)

### 4.2 검수 판정 기준
LLM이 각 건에 대해 아래 항목을 확인하고 `pass` / `flagged` 판정 + 사유를 반환
- 필수 필드 누락 여부 (제목/회사/마감일 등)
- 텍스트 이상 (HTML 태그 잔존, 인코딩 깨짐, 문장 잘림)
- 회사명-공고 내용 불일치 의심 (셀렉터가 엉뚱한 데이터를 긁어온 경우 — 사이트 구조 변경 감지 신호로도 활용 가능)
- 중복/유사 공고 의심 — 임베딩(기존 정규화 단계에서 계산된 벡터)으로 유사도 상위 후보를 1차 필터링한 뒤, 해당 후보들만 LLM에 함께 제공해 최종 판단하도록 함 (전수 비교 없이 후보군만 LLM에 넘겨 비용 절감)

### 4.3 배치 처리
- 1건씩 LLM 호출하지 않고, 여러 건을 하나의 프롬프트에 묶어 배치로 처리
- 응답은 구조화된 JSON 배열로 강제: `[{id, status: "pass"|"flagged", reason}, ...]`
- 배치 크기는 설정 가능한 값으로 (기본값 예: 30건), 프롬프트 길이가 너무 길어지지 않도록 조정

### 4.4 검수 상태 표시
- 데이터 테이블에 "검수 상태" 컬럼 추가: 미검수 / 정상 / 플래그됨
- 플래그된 건은 사유(reason)를 툴팁 또는 상세 보기에서 확인 가능
- 상태별 필터링 지원 (플래그된 것만 보기 등)

## 5. 데이터 모델 변경 (기존 PRD 확장)

```
normalized_jobs 테이블에 컬럼 추가
- review_status (unreviewed / pass / flagged, 기본값 unreviewed)
- review_reason (플래그 사유, nullable)
- reviewed_at (검수 시각, nullable)
```

## 6. 비기능 요구사항

- LLM 호출 실패(타임아웃, 응답 파싱 실패) 시 해당 배치는 재시도 또는 "검수 실패" 상태로 표시 (무한 재시도 방지)
- 검수는 정규화 데이터에 대해서만 수행 (원본 raw 데이터는 대상 아님)
- 대량 일괄 검수 시 LLM API 호출이 몰리지 않도록 배치 간 간격/동시성 제한 적용

## 7. 미결정 사항 (Open Questions)

- 검수 결과를 자동으로 신뢰할 임계치가 있는지 (예: "정상" 판정이어도 일정 확률로 사람이 샘플링 재확인할지)
- 정규화 직후 자동 검수를 나중에 추가할지, 계속 수동 트리거로 유지할지
- 검수에 사용할 LLM 모델과 배치 크기별 비용/정확도 트레이드오프
- 유사 공고 판정 시 임베딩 유사도 임계값 기준
