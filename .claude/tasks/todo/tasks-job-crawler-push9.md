## 결정 변경 기록

Push 6 은 "CSS 를 만들지 않는다" 는 결정으로 진행됐다. 그 결과 화면이 브라우저 기본 렌더링
그대로라 읽기 어렵다는 판단이 나왔고, 사용자가 2026-08-22 에 결정을 뒤집었다.
**Push 6 의 CSS 비목표 결정은 이 Push 로 대체된다.**

## 빌드 단계를 만들지 않는다

`.claude/rules/core.md` 는 빌드 단계 도입을 금지한다. 따라서 Tailwind CLI 나 PostCSS 파이프라인을
넣지 않는다. `<script src="https://cdn.tailwindcss.com">` 로 브라우저에서 직접 받는다.

HTMX 를 이미 CDN 에서 받고 있으므로 같은 방식이고, 컨테이너는 그대로 하나다.
Tailwind 가 프로덕션용으로 권하지 않는 방식이라는 것은 알고 있으나, 이 화면은 운영자 한 명이
쓰는 내부 도구이고 공개 트래픽이 없다 (`.claude/rules/core.md`).

## 동작을 바꾸지 않는다

이 Push 는 **보이는 것만 바꾼다.** 라우터, 조각의 id, `hx-get`·`hx-post`·`hx-target`·`hx-swap`
속성, 응답 구조를 바꾸지 않는다. Push 6 이 확인한 부분 갱신이 전부 그대로 돌아야 한다.

마크업을 재구성해야 스타일이 붙는 경우에도 조각의 경계와 id 는 유지한다.
바뀌는 것은 클래스 속성이다.

          생성 실패(502)는 화면에 아무것도 남기지 않는다. 사용자는 눌렸는지조차 알 수 없다
        - 2026-08-22 확인: 한화 등록이 502 `missing_field` 로 끝났는데 화면에는 변화가 없었다

          5xx 는 진짜 서버 결함에 남긴다. `/api/` 의 상태 코드 의미는 바꾸지 않는다 —
          그쪽은 소비 측과 스크립트가 읽는다

          한 자리에 사유를 띄운다. 조용히 사라지는 경로가 없어야 한다
        - 오류 문구는 무엇이 왜 실패했고 다음에 무엇을 할 수 있는지 적는다.
          "정적 HTML 에서 목록을 찾지 못했다" 는 "500 Internal Server Error" 보다 쓸모 있다
