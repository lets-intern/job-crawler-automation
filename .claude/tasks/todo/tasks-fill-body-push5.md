> 상태: 대기

## 배경 (PRD 를 안 봐도 되도록)

두 가지를 화면에 낸다.

**1. 크롤러마다 어떤 방식으로 도는지.** 지금은 `list_mode`/`detail_mode` 값이 있어도 화면에서
읽기 어렵다. 낱말로 적는다.

| 무엇 | 값 |
|---|---|
| 목록을 얻는 법 | `목록 API` / `목록 렌더` / `정적 목록` |
| 상세로 가는 법 | `상세 API` / `링크` / `항목 속성` |
| 마지막으로 확인한 때 | `2026-08-25 09:14 KST` |

**2. 무엇이 왜 실패했는지.** Push 1 이 만든 `crawl_run_failures` 를 보인다. 몇 건인지,
사유가 무엇인지, **어느 공고인지**(제목·주소)를 같이 적는다.

건너뛴 수(`skipped_count`)는 **실패와 따로** 보인다. 건너뜀은 정상이고 실패는 고칠 것이다.

- `app/api/ui_tests.py` - 테스트 실행 화면
- `app/api/ui_workflows.py` - 워크플로우 화면

- `app/templates/fragments/test_result.html`, `test_targets.html`
- `app/templates/fragments/workflow_card.html`, `workflow_list.html`

  이것을 쓴다**
- `app/api/ui.py` - `NEXT_STEPS` 에 사유별 다음 행동이 있다. `as_time` 필터가 시각을 그린다

## 지켜야 할 것

- **이모지·아이콘 금지.** 상태는 `성공` / `실패` / `건너뜀` 처럼 글자로 쓴다. 색만으로
  구분하지 않는다 (`.claude/rules/writing.md`)
- 시각은 반드시 `as_time` 필터를 거친다. 안 거치면 UTC 로 나온다
- 표는 제 안에서 가로로 스크롤한다. 페이지 본문이 가로로 밀리지 않게 한다
- Tailwind 클래스만. 빌드 단계를 만들지 않는다
- 브라우저 `confirm()` 을 새로 쓰지 않는다. `<dialog>` + HTMX 방식을 따른다
