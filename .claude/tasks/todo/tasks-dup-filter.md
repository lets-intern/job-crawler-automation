# Tasks: 검수 화면에서 중복을 찾는다

> 브랜치: `feat/dup-filter` (`feat/auto-register` 에서 딴다)
> 상태: 진행 중

## 왜 필요한가

수집이 늘면서 같은 공고가 여러 번 보이는지 확인할 길이 없다. 지금 640건을 세어 보면 이렇다.

| 무엇이 같은가 | 묶음 | 여분 |
|---|---|---|
| `source_url` | 0 | 0 |
| `content_hash` | 0 | 0 |
| **제목 + 회사** | 1 | 4 |
| **제목만** | 7 | 15 |

`source_url` 과 `content_hash` 가 0인 것은 **중복 판정이 제대로 돌고 있다는 뜻**이다. 파이프라인
버그가 아니다.

제목이 같은 것들은 이렇다.

```
'R&D분야 외국인 경력사원 채용'  x7   삼성 계열사별로 따로 올린 공고
'상시 인재 Pool 등록'          x5   한화 계열사별
'Business Operations Manager'  x2
'IT Manager'                   x2
```

**이것들은 진짜 중복이 아닐 수 있다.** 삼성전자 DX부문과 삼성SDI가 각각 올린 공고는 제목이
같아도 다른 공고다. 그래서 **자동으로 지우지 않는다.** 운영자가 보고 판단할 수 있게만 한다.

## 무엇을 만드나

데이터 검수 화면(`/review`)에 **중복 조건**을 더한다. 이미 있는 조건들(워크플로우·회사·진행
여부·빈 값 등) 옆에 붙는다.

기준을 고를 수 있어야 한다. 무엇을 중복으로 볼지가 상황마다 다르다.

| 기준 | 무엇을 잡나 |
|---|---|
| 제목 + 회사 | 같은 회사가 같은 제목으로 두 번 올린 것. 가장 좁고 확실하다 |
| 제목 | 계열사가 나눠 올린 것까지 잡는다. 넓다 |
| 원본 주소 | 파이프라인이 고장 났을 때만 걸린다. 지금은 0건이다 |

**묶음이 보여야 한다.** 중복 15건을 늘어놓으면 어느 것과 어느 것이 짝인지 모른다. 같은 값을
가진 것끼리 붙어 보이거나, 묶음마다 몇 건인지 적혀야 한다.

## 관련 파일

- `app/api/review_filter.py` - 조건을 읽고 SQL 을 만드는 자리. `read_filter` 와 `JobFilter`
- `app/api/review.py` - 검수 화면 라우트
- `app/templates/fragments/review_filters.html` - 조건 입력칸
- `app/templates/fragments/review_table.html` - 표
- `app/templates/macros.html` - 공통 매크로. 새로 만들지 말고 쓴다

## 지켜야 할 것

- **자동으로 지우지 않는다.** 계열사가 각각 올린 공고를 중복으로 지우면 진짜 공고가 사라진다
- 이미 있는 지우기(고른 것·조건 전체·워크플로우)와 **같이 쓸 수 있어야 한다.** 중복으로 걸러
  놓고 그중 몇 개를 고르는 것이 실제 쓰임이다
- 이모지·아이콘 금지. 상태는 글자로 (`.claude/rules/writing.md`)
- 시각은 `as_time` 필터를 거친다
- 표는 제 안에서 가로로 스크롤하고 본문은 가로로 밀리지 않는다
- 페이지 이동이 이미 있다. 중복 조건에서도 조건이 유지돼야 한다
