# PRD: 수집은 최소한, 나누는 것은 LLM 이 한다

> 작성일: 2026-08-26
> 대체: `.claude/tasks/todo/prd-split-body.md` (Push 1·2 로 만든 칸은 그대로 쓴다)
> 근거: 348건 실측, 열한 사이트 픽스처 대조

## 왜 바꾸나

칸마다 사이트별로 매핑을 적는 방식을 Push 1·2 에서 해봤다. **절반도 못 채웠다.**

| 칸 | 열한 곳 중 채우는 곳 |
|---|---|
| 자격요건 · 기타 | 8 |
| 직군 · 근무지 · 주요업무 · 전형절차 | 7 |
| 경력 | 5 |
| 고용형태 · 모집인원 · 우대사항 | 4 |
| 조직·부서 | **2** |

그리고 매핑을 적는 판단이 **사이트 11곳 × 칸 16개 = 176번**이다. 그중 다섯 곳에서 뜻이 다른
칸에 값이 들어가 있었다 — 한화 `부서`에 근무지, SK `부서`에 직무, 네이버 `회사`에 부서,
두산 `마감일`에 `지원자 개별일정`, 우아한형제들 `마감일`에 `기간제 영입 종료시`.

**사람이 176번 판단하면 그중 몇 번은 틀린다.** 사이트가 하나 늘 때마다 16번이 더 는다.

## 무엇으로 바꾸나

**수집은 어느 사이트나 확실히 주는 것만 한다. 나누는 것은 LLM 이 본문을 읽고 한다.**

```
크롤링:  제목 · 본문 · 모집시작일 · 모집마감일 · 회사명 · 원본주소
분류:    본문을 LLM 이 공통 항목으로 나눈다
나머지:  etc 로 모은다
```

## 왜 이 여섯인가

| 칸 | 열한 곳 중 | 왜 수집으로 두나 |
|---|---|---|
| 제목 | 11 | 어디나 준다 |
| 본문 | 11 | 분류의 재료다 |
| 모집 마감일 | 11 | 마감 지난 공고 건너뛰기가 이 값에 걸려 있다 |
| 모집 시작일 | 10 | 목록 응답에 공짜로 있다 |
| **회사명** | 9 | **본문에서 못 뽑는다** (아래) |
| **원본 주소** | 11 | `content_hash` 와 알림 링크가 걸려 있다 |

**회사명은 본문에 없다.** 348건을 세어보니 본문에 회사명이 글자로 나오는 것은 **32%** 뿐이다.

| 사이트 | 본문에 회사명이 있는 비율 |
|---|---|
| 현대 | 100% |
| 삼성 | 81% |
| 롯데 | 76% |
| 두산 | 53% |
| LG | 36% |
| 한화 | 25% |
| **SK** | **0%** (103건 중 1건) |

본문은 직무 설명이라 회사 이름을 적지 않는다. **없는 글자는 LLM 도 못 뽑는다.** 반면 목록
응답에는 `companyName`·`sdNm`·`corpName` 으로 깨끗하게 있다. 계열사 구분(LG유플러스 /
LG CNS, 한화생명 / 한화시스템)이 이 서비스가 주는 값이라 버릴 수 없다.

## 나누는 항목

Push 1 이 만든 칸을 그대로 쓴다. 마이그레이션이 이미 적용돼 있다 (0011·0012).

`job_category` `work_location` `career_level` `employment_type` `headcount`
`duties` `preferred` `hiring_process` `requirements` `department` `etc_info`

**어디에도 안 맞는 것은 `etc_info` 로 모은다.** 항목을 늘리지 않는다.

**본문 원문은 그대로 남는다.** 분류가 틀렸다고 판명되면 재크롤링 없이 다시 돌린다.

## 지어내지 않는다

**본문에 없는 것은 빈 칸이다.** 모델이 그럴듯하게 채우면 소비 측이 그것을 사실로 노출한다.

받은 결과를 그 자리에서 검증한다 — 뽑았다는 값이 본문에 실제로 있는지 본다
(`.claude/rules/llm.md` 의 "낸 것은 반드시 그 자리에서 돌려 본다").

## 비용

측정값이 있다 (`.claude/docs/ocr-benchmark.md`). 공고당 약 **4,453 토큰**, 5.1초.

400건이면 178만 토큰 한 번. 그다음부터는 새 공고만 — 이미 저장한 공고는 상세를 열지 않으므로
분류도 하지 않는다.

**모든 호출을 기록한다.** 제공자·모델·기능·입력·출력 토큰·지연 (`.claude/rules/llm.md`).
지금은 셀렉터 생성만 비싼 호출이었는데 이제 공고마다 하나씩 붙는다.

## 무엇이 사라지나

Push 2 가 쓴 **사이트별 칸 매핑**이 사라진다. 남는 것은 위 여섯 개뿐이다.

`seeds/site-configs-20260826.json` 의 칸 매핑이 그것이다. **지우기 전에 왜 지우는지 적어 둔다** —
그 파일을 만든 작업이 사흘 전이고, 다음 사람이 "왜 애써 만든 걸 지웠지" 라고 묻는다.

## 끝났다고 말할 수 있는 조건

1. 열한 사이트가 여섯 칸만 수집한다
2. 본문이 있는 공고는 분류를 거친다
3. **분류가 채운 값이 본문에 실제로 있다.** 지어낸 값이 없다
4. 본문에 없는 항목은 빈 칸이다
5. 회사명이 열한 곳 중 아홉 곳에서 채워진다 (토스·우아한형제들은 목록이 주지 않는다)
6. 호출마다 토큰과 지연이 기록된다
7. 제공 API 로 전량을 훑어 제목·본문·마감일·원본주소가 0건 비어 있다

## 열려 있는 것

**토스·우아한형제들의 회사명.** 목록이 주지 않는다. 크롤러 이름(`토스`·`우아한형제들`)으로
대신 채울지, 비울지 정해야 한다.

**분류를 언제 돌리나.** 수집과 같은 실행에서 이어 돌릴지, 따로 돌릴지. 같이 돌리면 실행이
공고 수만큼 길어지고, 따로 돌리면 분류 안 된 공고가 잠시 존재한다.

**실패한 분류를 어떻게 하나.** 모델이 응답하지 않거나 형식이 틀렸을 때 그 공고를 어떻게 둘지.
본문은 있으므로 나중에 다시 돌릴 수 있다.
