# Tasks: 본문 채우기 - Push 3

> PRD: `.claude/tasks/todo/prd-fill-body.md`
> Push 범위: 등록할 때 클릭해서 상세로 가는 길을 스스로 알아낸다 (셀렉터·경로 발견)
> 상태: 대기

## 배경 (PRD 를 안 봐도 되도록)

운영자가 상세 URL 을 찾아 넣지 않게 한다. 등록할 때 이 순서로 시도한다.

1. 목록을 `httpx` 로 받는다. 항목과 상세 주소가 다 있으면 끝이다. 브라우저를 띄우지 않는다
2. 항목이 없거나 상세 주소를 만들 값이 없으면 렌더한다
3. 그래도 없으면 **항목을 클릭한다.** 그 순간 나가는 요청을 확인해 경로를 알아낸다
4. 알아낸 요청을 `httpx` 로 다시 불러 같은 응답이 오는지 확인한다

**클릭은 등록할 때 한 번**이고 매 실행마다 하지 않는다.

### 성공 판정이 "주소가 바뀌었나" 가 아니다

2026-08-25 측정에서 삼성은 클릭해도 주소가 그대로였다. 모달을 열기 때문이다. 주소만 보면
실패로 판정되는데 실제로는 본문이 1,620자에서 9,798자로 늘고 공고 번호가 담긴 요청이 나간다.

**셋 중 하나면 도달한 것이다.**

| 신호 | 해당 사이트 |
|---|---|
| 주소가 바뀐다 | LG, 한화, 롯데 |
| 새 탭이 열린다 | SK |
| 요청이 나가거나 본문이 늘어난다 | 삼성 |

셋 다 없을 때만 `detail_unreachable` 이다.

### 클릭하면 안 되는 경우

현대는 항목의 첫 `a` 들이 SNS 공유 버튼(`href="javascript:;"`,
`onclick="shareSns('facebook', ...)"`)이라 눌러도 이동하지 않는다. **항목 속성으로 URL 을 만들
수 있으면 클릭하지 않는다.** 현대는 `data-recuyy`·`data-recutype`·`data-recucls` 가 상세 URL 의
세 파라미터다.
