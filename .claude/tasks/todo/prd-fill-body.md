# PRD: 본문 없는 공고를 없앤다

> 작성일: 2026-08-25
> 기준 버전: v0.1.0 (`d5d61eb`) 이후 `feat/ocr-crawling`
> 측정 근거: `.claude/docs/ocr-benchmark.md`, `.claude/site-recipes/`

## 목표

`normalized_jobs.body` 가 빈 공고를 0 으로 만들고, 앞으로도 생기지 않게 한다.

## 지금 상태 (2026-08-25, 216건)

| 사이트 | `source_url` | 건수 | 본문 없음 |
|---|---|---|---|
| LG | 목록 주소 | 83 | **83** |
| LG | 상세 주소 | 89 | 0 |
| 삼성 | 목록 주소 | 3 | **3** |
| SK | 상세 주소 | 20 | 0 |
| 롯데 | 상세 주소 | 8 | 0 |
| 현대 | 상세 주소 | 20 | 0 |
| | | | **합계 86** |

**본문 없음 86건은 목록 주소를 가진 86건과 정확히 같다.** 상세에 도달한 137건은 하나도 비지
않았다. 규칙이 단순하다 — **상세에 도달하면 본문이 있고, 못 하면 없다.**

제목·회사·마감은 216건 전부 채워져 있다. 소비 측 계약에 필요한 값은 이미 나온다.

## 비목표

여기 있는 것들은 지금 하지 않는다. 구상과 근거는 `.claude/tasks/memos/prd-crawler-v2-보류.md`
에 남겨 두었다.

- **본문을 13개 항목으로 나누는 것.** 롯데·SK·현대는 지금 셀렉터로 본문을 다 뽑고 있다.
  나누기 전에 채우는 것이 먼저다
- **LLM 분류.** 나누지 않으므로 부를 일이 없다. 이 PRD 의 작업은 토큰을 쓰지 않는다
- **AI 제공자 넷 고르기, 호출 로그 DB, 운영 설정 하위 메뉴, CSV 일괄 등록**
- OCR. 측정에서 글자를 틀렸다
- 다중 사용자 권한, 로그인·CAPTCHA 우회

## 1. 삼성이 상세에 도달하게 한다

삼성 3건이 목록 주소만 가진 이유는 상세로 가지 못해서다. 2026-08-25 측정에서 길이 확인됐다.

**클릭하면 모달이 열린다. 주소는 바뀌지 않는다.** 본문이 1,620자에서 9,798자로 늘고 요청이
나간다.

```
GET https://www.samsungcareers.com/recruit/detail.data?seqno=22878&strCode=
  -> 200, 39,490B, data.result 에 필드 41개
```

`22878` 은 항목의 `a[data-value="22,878"]` 에서 쉼표를 뺀 값이다. 이 요청은 브라우저 없이
`httpx` 로 200 이다. 자세한 것은 `.claude/site-recipes/www-samsungcareers-com.md` 에 있다.

목록도 브라우저 없이 된다 — `POST /hr/list.data`, 폼 형식, HTML 조각 17,935바이트.
파라미터가 하나라도 빠지면 500 이 오므로 여덟 개를 다 보낸다.

## 2. 성공 판정을 고친다

지금 판정은 "주소가 바뀌었나" 다. **삼성은 모달을 열어서 주소가 그대로이므로 실패로 읽힌다.**

셋 중 하나면 도달한 것이다.

| 신호 | 해당 사이트 |
|---|---|
| 주소가 바뀐다 | LG, 한화, 롯데 |
| 새 탭이 열린다 | SK |
| 요청이 나가거나 본문이 늘어난다 | 삼성 |

셋 다 없을 때만 실패다.

## 3. 상세에 도달하는 길을 등록할 때 알아낸다

운영자가 상세 URL 을 찾아 넣지 않게 한다. 순서는 이렇다.

1. 목록을 `httpx` 로 받는다. 항목과 상세 주소가 다 있으면 끝이다. 브라우저를 띄우지 않는다
2. 항목이 없거나 상세 주소를 만들 값이 없으면 렌더한다
3. 그래도 없으면 **항목을 클릭한다.** 그 순간 나가는 요청을 확인해 경로를 알아낸다
4. 알아낸 요청을 `httpx` 로 다시 불러 같은 응답이 오는지 확인한다. 되면 이후 실행은 그 경로다

**클릭은 등록할 때 한 번**이고 매 실행마다 하지 않는다. 모자란 것을 알아내는 수단이다.

측정 결과 여섯 사이트가 이렇게 갈린다.

| 사이트 | 상세로 가는 법 | 브라우저 없이 |
|---|---|---|
| 롯데 | 항목의 `<a href>` | 200, 0.04초 |
| 현대 | 항목의 `data-recuyy`·`data-recutype`·`data-recucls` 로 URL 조립 | 200 |
| SK | 항목의 `<a>` (새 탭으로 열림) | 확인됨 |
| LG | 클릭이 알려준 `POST .../retrieveJobNoticesDetail` | 200 |
| 한화 | 클릭이 알려준 `POST .../get-rcrt` | 200 |
| 삼성 | 클릭이 알려준 `GET /recruit/detail.data?seqno=` | 200 |

현대는 클릭하면 안 된다. 항목의 첫 `a` 들이 SNS 공유 버튼이라 눌러도 이동하지 않는다.

## 4. 본문을 못 얻으면 실패로 남긴다

상세에 도달하지 못했거나 도달했는데 읽을 것이 없으면 **실패로 기록한다.** 목록에서 읽은 값만
넣고 성공으로 넘기지 않는다. 지금 86건이 그렇게 쌓였다.

| 실패 | 뜻 |
|---|---|
| `list_empty` | 목록에서 반복 항목을 못 잡았다 |
| `detail_unreachable` | 링크·속성·클릭 어느 것으로도 상세에 못 갔다 |
| `detail_empty` | 상세에 갔는데 본문이 비었다 |
| `transport` | 사이트에 닿지 못했다 |

## 5. 어떤 방식으로 도는지 화면에 적는다

크롤러 목록·상세, 테스트 실행 결과, 워크플로우 카드에 적는다. 낱말로 적고 색이나 아이콘으로
구분하지 않는다 (`.claude/rules/writing.md`).

| 무엇 | 값 |
|---|---|
| 목록을 얻는 법 | `목록 API` / `목록 렌더` / `정적 목록` |
| 상세로 가는 법 | `상세 API` / `링크` / `항목 속성` |
| 마지막으로 확인한 때 | `2026-08-25 09:14 KST` |

경로는 등록할 때 정해지고 운영자가 바꿀 수 있다. **바꾼 것을 자동 판정이 덮어쓰지 않는다.**

## 6. 마감된 공고는 상세를 열지 않는다

목록에서 모집 기간이 끝난 항목을 걸러 상세로 가지 않는다. 이미 저장한 공고도 열지 않는다.

**날짜를 읽지 못한 항목은 진행 중으로 본다.** 못 읽은 것과 지난 것은 다르다. 날짜 형식이 바뀐
사이트를 조용히 전부 버리는 것이 이 기능의 유일한 위험이다.

건너뛴 수를 실행 기록에 남기고 **실패와 구분해** 보인다. 이 숫자가 없으면 형식이 바뀌어 전부
걸러진 사이트가 "새 공고 0건" 으로 보인다.

## 7. 이미 쌓인 86건을 정리한다

**LG 83건은 지운다.** 상세로 갈 길이 없던 시절 목록만 긁은 행이고, 같은 공고가 상세 주소를
가진 89건으로 이미 다시 들어와 있다. 데이터 검수 화면의 빈 값 조건으로 골라 지운다.

**삼성 3건은 다시 수집한다.** 1번이 끝나면 상세에 도달하므로 본문이 채워진다.

`raw_jobs` 는 append-only 다. 지우는 것은 운영자가 화면에서 고른 행뿐이고, 파이프라인이
고쳐 쓰지 않는다 (`.claude/rules/data-safety.md`).

## 끝났다고 말할 수 있는 조건

1. `normalized_jobs` 에서 `body` 가 빈 행이 **0건**이다
2. 삼성 공고에 본문이 들어 있다
3. 여섯 사이트를 1회씩 돌려 새로 들어온 행에 본문이 다 있다
4. 상세에 도달하지 못한 건이 있으면 **실패로 기록되어 화면에 보인다**
5. 크롤러마다 어떤 방식으로 도는지 화면에 적혀 있다

## 8. 채울 수 있는 값은 다 채운다

**롯데 자격요건을 채운다.** 8건 중 7건이 비어 있고 원인은 `detail.requirements` 셀렉터가 빈
값이라 아예 뽑지 않는 것이다.

**한화를 등록한다.** 목록·상세 API 를 둘 다 확인했다. 20건이 새로 들어온다.

## 9. 여섯 사이트 전부 목록 API 가 있다

2026-08-25 에 마지막 두 곳을 확인했다. **매 실행에 브라우저가 필요한 사이트는 없다.**

| 사이트 | 목록 | 확인 |
|---|---|---|
| LG | `POST .../rmk/job/retrieveJobNoticesList` | 83건 |
| 한화 | `POST .../rcRecruit/search-rcrt` | 20건 |
| 삼성 | `POST /hr/list.data` (폼, HTML 조각) | 9건 |
| SK | `POST /Recruit/GetRecruitList` (폼, JSON) | **104건** |
| 현대 | `GET /api/rec/AP-HM-FO-02730?hgrCd=1&lang=ko&...` | 파라미터 확인 필요 |
| 롯데 | 정적 HTML 로 이미 잡힌다 | 8건 |

**SK 는 지금 20건만 수집하고 있는데 API 는 104건을 준다.** 렌더된 목록이 첫 장만 보여 주기
때문이다. 이 PRD 를 적용하면 84건이 더 들어온다.

브라우저는 등록할 때 경로를 알아내는 순간에만 뜬다. 그 뒤 실행은 전부 `httpx` 다.

## 열려 있는 것

**현대 목록 API 의 파라미터.** 엔드포인트는 확인했고 본문 형식은 아직 확인하지 않았다.

**상세에 도달하지 못한 공고를 저장할 것인가.** 저장하지 않으면 "본문 없음 0" 이 유지되지만
무엇을 놓쳤는지 남지 않는다. 저장하면 본문 없는 행이 다시 생긴다. 실행 기록에 실패로 남기고
`raw_jobs` 에는 넣지 않는 쪽을 기본으로 본다.
