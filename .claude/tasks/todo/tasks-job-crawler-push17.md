## 왜 필요한가

생성 결과에 실패한 필드가 남으면 지금은 운영자가 셀렉터 JSON 을 직접 고쳐야 한다.
2026-08-22 QA 에서 롯데는 모델이 계열사 링크 목록을 잡았고, 사람이 브라우저로 HTML 을 열어
`ul.job-card-list` 를 찾아 손으로 넣었다. 그 일을 모델이 할 수 있다.

`.claude/rules/llm.md` 는 손 편집을 첫 번째 수단으로 두고, **요청 없이 재생성하지 말라**고
못박고 있다. 그래서 자동이 아니라 **운영자가 누르는 버튼**이다.

## 무엇을 고치는가

**실패한 필드만 고친다.** 잘 되는 필드를 다시 만들지 않는다. 모델이 한 번 맞춘 것을 두 번째
호출에서 잃는 일이 없어야 한다.

모델에게 주는 것.

- 지금 셀렉터 전체 (무엇이 이미 맞는지 알아야 그것을 피해 고른다)
- 실패한 필드 이름과 사유 — 0개 매칭인지, 링크에 href 가 없는지
- 정제한 HTML. 생성 때와 같은 정제·샘플링을 쓴다

받는 것은 **실패한 필드에 대한 새 셀렉터만**이다. 응답은 생성과 같은 스키마 검증을 거친다.

## 관련 파일

- `app/selector/repair.py` (신규) - 고치기 호출과 프롬프트
- `app/selector/generator.py` - 정제·호출·로그를 재사용한다. 두 번째 API 경로를 만들지 않는다
- `app/api/crawlers.py` - `POST /api/crawlers/{id}/repair`
- `app/api/ui_crawlers.py`, `app/templates/fragments/crawler_result.html` - AI 수정 버튼
