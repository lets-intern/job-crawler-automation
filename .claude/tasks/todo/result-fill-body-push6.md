# 결과: 본문 채우기 - Push 6

> 작업 파일: `.claude/tasks/todo/tasks-fill-body-push6.md`
> 실행: 2026-08-25 (KST). 운영 DB(포트 8000 컨테이너, `/data/jobs.db`)
> 판정: 성공

쌓인 수집 데이터를 비우고 여섯 사이트를 새 경로로 다시 채웠다. 제공 API 로 전체를 훑어
`title`·`company`·`deadline`·`body`·`source_url` 빈 건이 전부 0 이다.

## 왜 비웠나

작업 파일이 쓰인 시점의 "216건 중 86건 본문 없음" 은 실행 시점에 이미 해소돼 있었다. 그 86건
(LG 83, 삼성 3)은 Push 4·5 를 진행하는 동안 지워졌고, 실행 직전 본문 빈 건은 0 이었다.

그래도 비운 이유는 데이터가 두 경로에서 섞여 있었기 때문이다. 현대 20건과 롯데 8건이 옛 셀렉터
경로로 들어온 것이고, `source_url` 이 같아 재수집으로는 덮이지 않는다. 확인한 결과 현대 20건은
`source_url` 이 이전과 전부 같은데 본문은 20건 모두 달라졌다 — 옛 경로가 붙이던
`조직소개`/`직무상세` 머리말이 사라지고 API 가 주는 평문으로 바뀌었다. 비우지 않았다면 이 20건은
옛 값 그대로 남았을 것이다.

## 찾았지만 하지 않은 것

본문이 30자 미만인 공고가 9건 있다. 비어 있지 않으므로 QA 는 통과하지만 쓸 수 있는 값은
아니다 — 한화 8건과 LG 1건이고, 가장 짧은 것은 `0` 한 글자다
(`https://www.hanwhain.com/portal/apply/recruit/detail?rtSeq=19382`).

이번 작업이 만든 것은 아니다. 비우기 전 백업에서 같은 `source_url` 을 찾아 보면 글자 수가
9건 모두 지금과 똑같다. 사이트의 상세 페이지 자체가 그렇게 비어 있다는 뜻이다. 이 Push 의
기준은 "본문 빈 건 0" 이라 범위 밖으로 두고 적어만 둔다.

현대 20건은 새 경로로 본문이 바뀌면서 옛 경로에 있던 `조직소개` 문단이 빠졌다. 본문 길이가
3,175자에서 2,075자로 줄어든 건이 그 예다. 직무 설명(`privJdDtl`)과 자격요건은 그대로 들어오고
`requirements` 도 채워진다. 조직 소개가 필요한 값인지는 판단이 필요한 자리라 손대지 않았다.

데이터만 다뤘고 코드를 고치지 않았다.
