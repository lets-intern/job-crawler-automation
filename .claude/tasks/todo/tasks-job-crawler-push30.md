## 배경

두 화면이 같은 데이터를 두 벌로 보여준다. 조회는 필터와 삭제, 검수는 수정인데, 목록·상세
모달·시각 표시가 겹친다. 하나로 합쳐 **데이터 검수** 하나만 남긴다.

수집이 제대로 됐는지 보려면 **값이 빈 공고를 찾을 수 있어야 한다.** 셀렉터가 한 필드만 놓쳤을 때
지금은 148건을 눈으로 훑는 것 말고 방법이 없다.

## 30.1 두 화면 비교

합치기 전에 두 화면이 각각 무엇을 들고 있는지 나란히 적는다. 판정은 세 가지다 —
`옮김`(합친 화면에 그대로 있다), `버림`(표에서 없어진다. 어디로 갔는지 함께 적는다),
`새로`(둘 다 없던 것).

### 조회 조건

| 조건 | 데이터 조회 `/jobs` | 데이터 검수 `/review` | 판정 |
|---|---|---|---|
| 워크플로우 | 있음 | 있음 | 옮김. 하나로 겹친다 |
| 회사 | 있음 | 있음 | 옮김. 하나로 겹친다 |
| 검색어 (제목·회사·부서) | 있음 | 있음 | 옮김. 하나로 겹친다 |
| 진행 여부 (마감일) | 있음 | 없음 | 옮김 |
| 전달 여부 | 있음 | 없음 | 옮김 |
| 수집 시각 범위 | 있음 | 없음 | 옮김 |
| 정규화 시각 범위 | 있음 | 없음 | 옮김 |
| 정렬 기준 넷·방향 | 있음 | 없음 (미전달 우선 고정) | 옮김. 검수 순서를 기본값으로 더한다 |
| 페이지 크기·페이지 이동 | 없음 (100건 상한) | 있음 | 옮김 |
| 빈 값인 필드 | 없음 | 없음 | 새로 |

### 표의 열

| 열 | 데이터 조회 | 데이터 검수 | 판정 |
|---|---|---|---|
| 고르기 체크박스 | 있음 | 없음 | 옮김 |
| 번호 | 있음 | 있음 | 옮김 |
| 회사·제목·부서·마감 | 값만 | 값 + 규칙값/사람 보정 | 검수 쪽을 옮긴다 |
| 본문·자격요건 | 열 없음 | 있음 | 옮김 |
| 보정 개수 | 없음 | 있음 | 옮김 |
| 전달 | 있음 | 있음 | 옮김. 검수 쪽이 보정 미전달까지 적는다 |
| 워크플로우 | 있음 | 있음 | 옮김 |
| 수집 시각 | 없음 | 있음 | 옮김 |
| 원문 | `원문 열기` 링크 | 주소 그대로 | 검수 쪽을 옮긴다 |
| 회사명 출처 | 열 있음 | 모달에 있음 | 버림. 모달에 남는다 |
| 정규화 시각 | 열 있음 | 모달에 있음 | 버림. 모달에 남는다 |
| 상세 단추 | 있음 | 없음 (`수정` 이 같은 자리) | 버림. `수정` 이 대신한다 |

열 둘을 표에서 버리는 이유는 폭이다. 합치면 열이 열넷이고, 거기에 둘을 더하면 표가 가로로
흐르는 폭이 화면 두 배가 된다. 둘 다 모달이 이미 적고 있어 값을 못 보는 자리는 생기지 않는다.

### 새로 만드는 것

- 빈 값인 필드로 거르는 조건. 여섯 필드 중 하나를 고르거나 `아무 필드나` 를 고른다
- 필드별 빈 건수. 지금 조건에 걸린 행을 필드마다 세어 조건을 걸기 전에 보여준다
- 뜻이 있어서 빈 값일 수 있는 필드의 설명. 마감·부서·자격요건이 그렇다
