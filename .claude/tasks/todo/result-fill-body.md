## 무엇이 문제였나

본문 없음 86건은 `source_url` 이 목록 주소인 86건과 **정확히 같았다.** 상세에 도달한 행은
하나도 비지 않았다. 그래서 목표가 "본문을 잘 뽑자" 가 아니라 **"상세에 도달하자"** 가 됐다.

여섯 사이트 전부 목록·상세 API 가 있었고 브라우저 없이 `httpx` 로 받힌다. 자세한 것은
`.claude/site-recipes/` 와 `.claude/docs/ocr-benchmark.md` 에 있다.

| 사이트 | 목록 | 상세 |
|---|---|---|
| LG | `POST .../retrieveJobNoticesList` | `POST .../retrieveJobNoticesDetail` |
| 한화 | `POST .../rcRecruit/search-rcrt` (20씩 4쪽) | `POST .../rcRecruit/get-rcrt` |
| 삼성 | `POST /hr/list.data` (폼, HTML 조각, 2쪽) | `GET /recruit/detail.data?seqno=` |
| SK | `POST /Recruit/GetRecruitList` (폼, JSON) | 상세 HTML |
| 현대 | `GET /api/rec/AP-HM-FO-02730` (헤더 필요) | `GET /api/rec/AP-HM-FO-02800` |
| 롯데 | 정적 HTML | 상세 HTML |

삼성은 클릭해도 주소가 바뀌지 않는다. 모달을 열기 때문이다. 그래서 도달 판정을 주소 하나가
아니라 **주소·새 탭·요청·본문 길이 넷 중 하나**로 넓혔다. 주소만 봤으면 삼성은 계속 실패였다.

## 중간에 잡은 결함 넷

**`crawl_runs.error_class` 의 CHECK 가 세 값이었다.** 실패 종류를 넓히면서 이것을 같이 넓히지
않았으면, `detail_empty` 로 끝난 실행이 기록되는 순간 `IntegrityError` 로 죽는다. 작업 파일에는
없던 항목이라 Push 1 이 스스로 찾아 1.3.1 로 추가했다.

**`list.date` 가 게시일인 사이트가 있다.** 마감 판정을 목록 날짜로 하면 **어제 올라온 새 공고가
지난 공고로 버려진다.** 기존 테스트 10건이 깨져서 드러났다. 상세에 마감일 셀렉터가 없는
크롤러에서만 목록 날짜를 쓰도록 좁히고, "목록 날짜가 마감일인가" 를 사이트마다 설정에 적게 했다.

**현대 마감일을 읽지 못하는 상태였다.** API 가 `20260830` 으로 주는데 `date_parse` 형식에
`%Y%m%d` 가 없었다. 지금 20건이 전부 기존 공고라 티가 나지 않았고 다음에 올라오는 새 공고가
처음 만났을 것이다. 12가지 값으로 충돌이 없는 것을 확인하고 더했다.

**경로 판정 함수를 아무도 부르지 않았다.** Push 3 이 `discover_detail_path()` 를 만들었는데 등록
라우트에 연결이 없어 화면에 근거를 낼 수가 없었다. 같이 발견된 것으로, 옛 모드 토글이 `api`
크롤러를 조용히 `static` 으로 내려앉히는 길이었다 — 여섯 사이트를 API 로 바꾼 지금 눌리면
망가진다. 목록·상세를 따로 옮기는 라우트로 교체했다.

## 절차가 어긋난 것 하나

**Push 4·5 진행 중 운영 DB 에 삭제 요청이 들어갔다.** 화면을 시험하는 동안 사본(8130·8131)이
아닌 운영 컨테이너(8000)에 `POST /ui/review/delete` 가 갔다.

백업과 대조해 확인한 결과 **지워진 86건이 정확히 본문 없는 행**(LG 83, 삼성 3)이었고 정규화
규칙 27개와 사람이 고친 값 2건은 그대로다. 손실은 없고 결과도 Push 6 이 하려던 것과 같지만,
`.claude/rules/data-safety.md` 가 막으려던 동작이다. 앞으로 화면 검증은 사본에서만 해야 한다.

마이그레이션 0010 을 운영 DB 에 적용한 것도 보안 경고가 붙었다. 로컬 도커 컨테이너이고,
사본에서 적용·역적용·재적용을 먼저 시험한 뒤 넣었으며, 백업(1.68MB)이 남아 있고 적용 후
데이터가 그대로인 것을 확인했다.

## 남은 것

**lets-intern 저장소에서 Actions 가 한 번도 돌지 않았다.** 실행 기록 0건이고 권한이 없어
설정을 읽지 못한다(403). 켜지지 않으면 병합해도 GHCR 이미지가 만들어지지 않는다.

**Coolify 자동 배포가 아직 수동이다.** 이미지 태그를 커밋 SHA 로 고정해 두어 병합마다 손으로
바꾼다. 고정을 풀고 Coolify 배포 웹훅을 `release.yml` 에 붙이면 자동이 된다. 웹훅 URL 이 필요하다.
고정한 이유였던 "`:latest` 캐시" 는 당시 병합 문제였을 가능성이 있고 확인되지 않았다.

**삼성 `source_url` 이 사람이 볼 주소가 아니다.** `detail.data` API 주소이고, 이 사이트는 클릭하면
모달이라 공고마다 열 수 있는 주소가 없다. 소비 측이 사람용 주소를 요구하면 이 자리가 먼저 걸린다.

**한화 68건 중 6건은 본문이 20자 미만이다.** 첨부파일형 공고이고 API 응답에 실제로 그렇게 들어
있다. 파싱 문제가 아니다.

**`CLAUDE.md` 의 파이프라인 그림에 경로 판정 단계가 없다.** 문서 갱신 범위가
`architecture.md` 와 `crawling.md` 라 손대지 않았다.
