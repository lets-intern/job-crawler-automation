## 무엇이 어긋나 있나

2026-08-24 05:41 KST 에 화면을 보니 최근 실행이 `2026-08-23 20:15` 로 떠 있었다. 9시간 전이다.
SQLite `datetime('now')` 가 UTC 를 쓰고, 화면이 그 값을 그대로 그린다.

"방금 돌았나" 를 판단할 수 없다. 다음 실행 예정 시각도 마찬가지다.

## 저장은 UTC 로 둔다

**저장된 값을 바꾸지 않는다.** 두 가지가 걸려 있다.

`normalized_at` 은 제공 API 의 폴링 커서다. `.claude/docs/api-contract.md` 가 그 의미를 바꾸지
말라고 못박고 있다 — 소비 측이 그 값에 커서를 걸고 있어서, 값이 9시간 밀리면 이미 받은 것을
다시 받거나 못 받은 구간이 생긴다.

`content_hash` 와 무관한 다른 시각들도 UTC 로 두는 편이 낫다. 서버가 어느 지역에 뜨든 저장된
값은 같아야 하고, 데이터 파일을 다른 서버로 옮길 때도 시간대가 섞이지 않는다.

**바꾸는 것은 화면에 그리는 순간뿐이다.**

## 어디를 고치는가

시각을 그리는 곳이 여러 템플릿에 흩어져 있다. 한 곳에서 바꿔야 빠뜨리지 않는다.

Jinja2 필터를 하나 만들어 템플릿이 그것만 쓰게 한다. 각 템플릿에서 따로 계산하면 다음에
시각을 그리는 화면이 생길 때 또 UTC 가 샌다.

표시할 시간대는 설정에서 온다. 기본값은 `Asia/Seoul` 이다. 운영자가 한 명이고 그가 한국에
있다는 것이 이 서비스의 전제다 (`.claude/rules/core.md`).

## 관련 파일

- `app/api/ui.py` - Jinja2 필터 등록
- `app/config.py`, `.env.example` - 표시 시간대 설정
- `app/templates/` - 시각을 그리는 모든 곳
- `app/api/jobs.py` - **건드리지 않는다.** 제공 API 는 계약대로 UTC 다
