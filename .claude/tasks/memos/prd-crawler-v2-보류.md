# PRD: 크롤링 자동화 v2

> 작성일: 2026-08-24
> 기준 버전: v0.1.0 (`d5d61eb`)
> 측정 근거: `.claude/docs/ocr-benchmark.md`, `.claude/site-recipes/`

## 한 줄

목록 URL 하나만 받아 스스로 등록하고, 상세로는 클릭해서 들어가고, 본문은 LLM 이 읽어
13개 항목으로 나눈다. 셀렉터로 필드를 뽑는 일을 그만둔다.

## 왜 바꾸나

**셀렉터가 HTML 을 물고 온다.** `<a>` 태그와 마크업이 값에 섞여 들어온다. 지금은 정규화
규칙으로 걷어내고 있는데, 애초에 필드를 셀렉터로 오려내는 방식이 만든 문제다.

**상세 URL 을 사람이 찾아 넣어야 한다.** 목록에 링크가 없는 사이트가 있고(LG, 한화) 그때는
등록이 막혔다.

**셀렉터는 등록된 필드만 준다.** 지금 4개다. 13개를 얻으려면 사이트마다 13번 맞춰야 한다.

측정해 보니 셋 다 풀린다. 항목을 클릭하면 상세로 가고, 상세 텍스트를 LLM 에 넘기면 13개
항목을 채운다. 5.1초, 4,453 토큰, 원본과 글자까지 일치했다.

## 비목표

- **OCR 을 기본 경로로 쓰지 않는다.** 캡처해서 글자로 되돌리는 경로는 같은 공고 본문에서 글자를
  틀렸다(`유해요인` -> `유해요일`, `산업안전보건법상` -> `산업안전보건법`). DOM 텍스트는 원본과
  일치했다. 캡처는 **DOM 에 글자가 없는 공고**에만 남긴다
- 다중 사용자 권한 체계. 비밀번호 하나로 잠그는 지금 방식을 유지한다
- 로그인·CAPTCHA 우회
- 분산 크롤링, 큐 서버, 두 번째 컨테이너

## 1. httpx 로 먼저 받고, 모자란 것만 클릭으로 알아낸다

**`httpx` 를 없애지 않는다.** 순서는 이렇다.

1. 목록을 `httpx` 로 받는다. 항목과 상세 주소가 거기 다 있으면 끝이다. 브라우저를 띄우지 않는다
2. 항목이 없거나 상세 주소를 만들 값이 없으면 렌더한다
3. 그래도 상세 주소가 없으면 **항목을 클릭한다.** 그 순간 나가는 요청을 확인해 경로를 알아낸다

클릭은 **모자란 것을 알아내는 수단**이다. 등록할 때 한 번이고 매 실행마다 하지 않는다.
알아낸 뒤로는 그 요청을 `httpx` 로 부른다.

측정한 값으로 보면 정적으로 목록이 잡히는 곳은 롯데뿐이고(0.15초, 항목 8건, 링크 3개),
나머지 다섯은 정적 응답에 항목이 0건이라 2단계로 간다.

2026-08-24~25 에 여섯 사이트를 전부 측정한 결과다.

| 사이트 | 클릭이 하는 일 | 그때 나가는 요청 | 브라우저 없이 |
|---|---|---|---|
| LG | 페이지 이동 (1.6초) | `POST .../rmk/job/retrieveJobNoticesDetail` | 200 |
| 한화 | 페이지 이동 (2.6초) | `POST .../rcRecruit/get-rcrt` | 200 |
| 삼성 | **모달** (본문 1,620 -> 9,798자) | `GET /recruit/detail.data?seqno=22878` | 200, 필드 41개 |
| 롯데 | 페이지 이동 | 상세 HTML 문서 하나 | 200, 0.04초 |
| SK | **새 탭** | 상세 HTML 문서 하나 | 확인됨 |
| 현대 | 클릭 불필요 | 항목의 `data-*` 로 URL 을 만든다 | 200 |

현대는 항목에 `data-recuyy`·`data-recutype`·`data-recucls` 가 있고 그것이 상세 URL 의 세
파라미터다. 클릭할 필요가 없다.

### 성공 판정은 "주소가 바뀌었나" 가 아니다

삼성은 클릭해도 주소가 그대로다. 모달을 열기 때문이다. 주소만 보면 실패로 판정되는데 실제로는
공고 번호가 담긴 요청이 나가고 본문이 여섯 배로 늘어난다.

**셋 중 하나면 성공이다.**

| 신호 | 해당 사이트 |
|---|---|
| 주소가 바뀐다 | LG, 한화, 롯데 |
| 새 탭이 열린다 | SK |
| 요청이 나가거나 본문이 늘어난다 | 삼성 |

셋 다 없을 때만 실패다.

## 2. 못 가져오면 실패다

목록에서 항목을 못 잡거나, 클릭에 아무 반응이 없거나, 상세에서 읽을 것이 없으면 **실패로
기록한다.** 조용히 0건으로 넘기지 않는다.

| 실패 | 뜻 |
|---|---|
| `list_empty` | 목록에서 반복 항목을 못 잡았다 |
| `click_no_response` | 클릭했는데 주소·새 탭·요청·본문 어느 것도 바뀌지 않았다 |
| `detail_empty` | 상세로 갔는데 읽을 내용이 없다 |
| `classify_failed` | LLM 이 항목을 채우지 못했다 |
| `transport` | 사이트에 닿지 못했다 |

## 3. 사람이 수집 방식을 고르지 않는다

`list_mode` / `detail_mode` 를 운영자가 고르는 화면을 없앤다. 등록 과정이 1번의 순서대로
시도해 스스로 정한다.

등록할 때 운영자가 넣는 것은 **목록 URL 하나**다. 상세 URL 을 묻지 않는다.

등록 과정이 스스로 한다.

1. 목록을 `httpx` 로 받아 반복 항목을 찾는다. 잡히면 브라우저를 띄우지 않는다
2. 안 잡히면 렌더해서 다시 찾는다. 그래도 없으면 `list_empty` 로 실패
3. 항목에 상세 주소를 만들 값이 있으면(링크, `data-*`) 그것을 쓴다. 없을 때만 첫 항목을 클릭한다
4. 클릭 뒤 주소·새 탭·요청·본문 중 무엇이 바뀌었는지 본다. 아무것도 없으면 `click_no_response`
5. **그때 나간 요청을 줍는다.** 구조화된 응답이면 그 주소·본문 형식·필드 매핑을 저장한다
6. 줍은 요청을 `httpx` 로 다시 불러 같은 응답이 오는지 확인한다. 되면 이후 실행은 그 경로다
7. 구조화된 응답이 없으면 상세 텍스트를 LLM 에 넘겨 13개 항목을 받는다
8. 어느 쪽이든 받은 값을 대조해 필드별로 채워졌는지 센다. 0건인 필드는 이름과 함께 보인다

상세 URL 을 손으로 넣는 길은 남긴다. 클릭이 안 되는 사이트에 쓸 마지막 수단이다.

## 4. 목록 여러 개를 한꺼번에 등록한다

CSV 파일이나 텍스트 입력으로 목록 URL 을 여러 개 받는다. 순서대로 등록하고 테스트까지 돌린 뒤,
운영자가 **한 화면에서 결과를 보고 틀린 것만 고친다.**

한꺼번에 넣어도 사이트마다 딜레이는 그대로 지킨다.

## 5. 경로는 두 갈래고, 화면에 무엇으로 도는지 적는다

측정 결과 여섯 사이트가 둘로 갈린다.

| 경로 | 사이트 | 13항목을 얻는 법 | 공고당 토큰 |
|---|---|---|---|
| **구조화된 응답** | LG, 한화, 삼성 | 응답 필드를 매핑한다 | **0** |
| **텍스트 + LLM 분류** | 롯데, SK, 현대 | 상세 텍스트를 LLM 이 나눈다 | 약 4,453 |

롯데·SK·현대는 서버가 HTML 을 통째로 만들어 주는 방식이라 브라우저가 따로 부르는 API 가 없다.
클릭 뒤 XHR 이 0건이고 나가는 것은 상세 문서 요청 하나다. **그 셋은 LLM 분류가 대비책이 아니라
정규 경로다.**

두 경로 다 브라우저를 쓰지 않는다. 구조화된 응답도 상세 HTML 도 `httpx` 로 받는다.
브라우저는 등록할 때 한 번, 목록을 렌더하고 클릭해 보는 그 순간에만 뜬다.

### 화면에 표시한다

크롤러 목록과 상세, 테스트 실행 결과, 워크플로우 카드에 **그 크롤러가 어떤 방식으로 도는지**
적는다. 낱말로 적고 색이나 아이콘으로 구분하지 않는다 (`.claude/rules/writing.md`).

적을 것은 이만큼이다.

| 무엇 | 예 |
|---|---|
| 목록을 얻는 법 | `목록 API` / `목록 렌더` |
| 상세로 가는 법 | `상세 API` / `링크` / `항목 속성` / `클릭` |
| 13항목을 얻는 법 | `응답 매핑` / `LLM 분류` |
| 마지막으로 확인한 때 | `2026-08-25 09:14 KST` |

**LLM 분류를 쓰는 크롤러는 공고당 토큰이 든다는 것이 화면에서 보여야 한다.** 어느 사이트가
비용을 쓰는지 모르면 9번의 사용량 화면을 봐도 원인을 못 찾는다.

경로는 등록할 때 정해지고 운영자가 바꿀 수 있다. 바꾼 것을 자동 판정이 덮어쓰지 않는다.

## 6. 본문을 13개 항목으로 나눈다

| 항목 | 예 |
|---|---|
| 제목 | `[정보보안센터] IT보안 담당자 경력채용` |
| 상위 기업 | `LG` |
| 모집 기업 | `LG유플러스` |
| 조직 소개 | 우리 조직을 소개합니다 |
| 주요 업무 | 이런 일을 하시게 될 거예요 |
| 필수 조건 | |
| 우대 조건 | |
| 전형 절차 | |
| 고용 형태 | `계약직` |
| 근무지 | `서울특별시 강서구` |
| 기타 사항 | |
| 모집 시작일 | `2026.08.21 09:00` |
| 모집 마감일 | `2026.08.30 23:00` |

**있는 것만 채운다.** 페이지에 없는 항목은 빈 값이고 지어내지 않는다. 항목은 수집한 데이터를
보고 더 늘릴 수 있다.

**LLM 에 넘긴 원문 텍스트를 따로 저장한다.** 분류가 틀렸을 때 다시 볼 유일한 근거다.
`raw_jobs` 가 그 자리이고 append-only 규칙은 그대로다. 공고당 6KB 안팎이다.

분류와 정규화는 하는 일이 다르다. 분류는 "이 문단이 우대 조건이다" 를 정하고, 정규화는
"`2026.08.30 23:00` 을 `2026-08-30` 으로" 를 한다. **분류 뒤에 정규화 규칙이 돈다.**

## 7. 마감된 공고는 상세를 열지 않는다

목록에서 모집 기간이 끝난 항목을 걸러 **클릭하지 않는다.** 이미 저장한 공고도 클릭하지 않는다.
비용이 새 공고에만 들게 하는 장치다.

**날짜를 읽지 못한 항목은 진행 중으로 본다.** 못 읽은 것과 지난 것은 다르다. 날짜 형식이 바뀐
사이트를 조용히 전부 버리는 것이 이 기능의 유일한 위험이다.

건너뛴 수를 실행 기록에 남기고 **실패와 구분해** 보인다. 이 숫자가 없으면 형식이 바뀌어 전부
걸러진 사이트가 "새 공고 0건" 으로 보인다.

## 8. AI 제공자를 고른다

Claude, Qwen, Gemini, GPT 중에서 고른다.

**`.claude/rules/llm.md` 를 먼저 고친다.** 지금 그 파일에 "제공자는 Gemini 하나, 두 번째
제공자용 어댑터 층을 만들지 않는다" 가 명시돼 있다. 규칙을 두고 코드만 넣으면 다음에 또
충돌한다. 규칙 수정이 이 항목의 첫 작업이다.

제공자를 바꿔도 **낸 것을 그 자리에서 검증한다**는 규칙은 그대로다. 모델은 제안자다.

## 10. AI 호출을 기록하고 보여준다

호출마다 제공자·모델·기능·입력 토큰·출력 토큰·지연·성공 여부를 남긴다.

**운영 DB 와 별도의 SQLite 파일에 쓴다.** 로그가 운영 DB 에 섞이면 스냅샷 내보내기·가져오기가
무거워진다.

**보관 한도를 둔다.** 일정 크기나 기간을 넘으면 오래된 것부터 지운다. 화면에서 손으로 비우는
길도 둔다.

v1 은 셀렉터 생성이 유일한 비싼 호출이었다. v2 는 **공고마다 분류 호출이 하나씩 붙는다.**
숫자가 없으면 비용 질문에 답할 수 없다. 5번이 화면에 적는 경로 표시와 짝이다 — 어느 사이트가 토큰을 쓰는지 화면에서 보이고, 얼마나 썼는지 여기서 보인다.

## 11. 화면을 정리한다

지금 산발적이라 알아보기 어렵다. Push 28 이 크롤러 등록·테스트·워크플로우·규칙·설정을 한 번
정리했다. v2 에서 늘어나는 화면도 같은 규칙을 따른다.

기존 흐름은 그대로 둔다.

```
크롤러 생성 -> 테스트 -> 워크플로우 -> 정규화 -> 데이터 검수 -> 운영 설정
```

## 단계와 상태

**단계마다 워크플로우를 만들지 않는다. 공고 한 건에 상태를 둔다.**

```
발견 -> 텍스트 확보 -> 분류 -> 정규화 -> 검수 완료
```

스케줄러가 하는 일은 목록 파싱과 텍스트 확보까지다. 그 뒤는 사람이 밀거나, 검수를 꺼두면
자동으로 흐른다.

사람 검수가 스케줄 실행을 막으면 안 된다. 30분마다 도는데 검수에서 사람을 기다리면 다음 실행이
겹치고, 지금 구현은 겹치면 건너뛰므로 크롤링이 조용히 멈춘다.

**검수는 끄고 켤 수 있다.** 처음엔 켜서 품질을 보고 믿을 만해지면 끈다.

실패하면 그 자리에 멈추고 사유를 남긴다. 재시도는 **그 단계만** 다시 한다.

## 무엇이 사라지나

| 사라지는 것 | 이유 |
|---|---|
| `list_mode` / `detail_mode` 선택 화면 | 등록 과정이 정한다 |
| 필드별 CSS 셀렉터 (`detail.*`) | 응답 매핑이나 LLM 분류가 대신한다 |
| 셀렉터 AI 수정 | 고칠 셀렉터가 없다. 매핑과 분류 결과를 고치는 것으로 바뀐다 |

목록에서 항목을 찾는 셀렉터(`list.item`)는 남는다. 무엇을 클릭할지, 무엇이 한 건인지 정해야
한다.

## 열려 있는 것
