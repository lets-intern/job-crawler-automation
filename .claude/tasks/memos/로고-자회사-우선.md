# 로고는 자회사 이름 기준이다

> 2026-08-28 결정. 아직 구현하지 않았다.

## 정한 것

로고는 **자회사(`normalized_jobs.company`) 이름으로 찾는다.** 모회사 기준이 아니다.

찾는 순서가 셋이다.

1. 자회사 이름의 `companies` 행에 로고가 있으면 그것
2. 자회사 로고가 없거나 자회사 이름 자체가 비어 있으면 **모회사 로고**
3. 둘 다 없으면 로고 없음

## 왜

삼성 채용 사이트 하나에 삼성SDS 와 삼성전기 공고가 섞여 들어온다. 모회사 기준으로만 붙이면
그 둘이 같은 삼성 로고를 달고, 계열사를 가르려고 회사명을 두 칸으로 나눈 일
(`prd-fields-and-logo.md` 3절)이 화면에서 도로 무의미해진다.

폴백이 필요한 이유는 반대쪽이다. 토스·우아한형제들처럼 목록이 회사명을 주지 않는 사이트는
자회사가 비어 있고, 그때 로고까지 비면 그 사이트 공고 전부가 로고 없이 나간다.

## 지금 코드와 다른 점

`app/companies.py` 의 자동 등록은 이미 자회사가 있으면 자회사 이름으로, 없으면 모회사
이름으로 행을 만든다 (fields-and-logo Push 4). **행을 만드는 규칙은 맞고, 없을 때 모회사로
내려가는 폴백이 없다.**

지금은 자회사 행에 로고가 비어 있으면 그냥 로고가 없다. 그 자리에 2번 단계를 넣는 일이다.

## 어디를 고치는가

- 로고를 읽어 내보내는 자리 (제공 API 와 화면). 폴백은 **읽는 쪽**이 한다
- `companies` 표에 로고를 복사해 넣지 않는다. 복사하면 모회사 로고를 바꿔도 자회사가 옛
  로고를 든 채로 남는다
- 회사 화면(`/companies`)에 그 회사가 지금 **자기 로고를 쓰는지 모회사 것을 쓰는지** 적는다.
  적지 않으면 운영자는 로고가 이미 붙은 줄 알고 자회사 로고를 영영 올리지 않는다

## 아직 정하지 않은 것

제공 API 가 로고를 어느 필드로 내보내는가. `.claude/docs/api-contract.md` 에 아직 로고가
없다. 넣을 때 이 폴백이 API 쪽에서도 같은 순서로 도는지 함께 정한다.
