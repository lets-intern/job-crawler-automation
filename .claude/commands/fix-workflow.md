# 워크플로우 진단

## 대상

$ARGUMENTS

## 절차

1. `workflow-ops` 로 상태와 최근 실행 로그를 본다. **먼저 status, 손대는 건 그 다음이다**
2. 최근 실패의 `error_message` 를 분류한다 — 전송 실패 / 셀렉터 미스 / 파싱 실패
   (`rules/crawling.md` 가 세 가지를 정의한다)
3. 분류에 따라 나눈다
   - 전송 실패만 반복: 사이트 장애나 차단. 주기를 늘리고 관찰. 요청을 더 보내지 않는다
   - 셀렉터 미스: 워크플로우를 중지하고 `selector-generate` 로 재생성
   - 파싱 실패 또는 값이 지저분함: 셀렉터가 아니라 정규화 규칙 문제다
4. 조치 후 `crawl-test` 로 1회 검증한다
5. `site-recipe` 의 이력 표에 날짜·원인·조치를 남긴다

원인을 모른 채 재개하지 않는다.
