# PRD 기반 작업 목록 생성

PRD 를 **배포 단위 파일 분리** + **커밋 단위 하위 작업** 구조로 분해한다.

## 폴더

```
.claude/tasks/todo/     PRD 및 신규 task 파일
  prd-*.md
  tasks-<prd명>-<N>.md
.claude/tasks/done/     완료된 task + 결과 기록
```

## 절차

1. 인자로 받은 파일을 읽는다. 없으면 `todo/` 에서 최신 `prd-*.md` 를 찾는다
2. 독립 배포 가능한 단위로 파일을 나눈다. 단위당 하위 커밋 3~7개
3. 각 하위 작업 = Git 커밋 하나. 파일 5개 미만, 독립 검증 가능
4. 구현 작업 뒤에 검증 작업을 붙인다

## 이 서비스에서의 분해 기준

파이프라인 단계가 곧 배포 단위다. 셀렉터 생성 / 크롤링 실행 / 워크플로우 스케줄링 / 정규화 /
조회 화면 / 외부 제공 API. 한 파일이 두 단계를 걸치면 잘못 나눈 것이다.

검증 작업은 대상에 따라 다르다. 이걸 뭉뚱그리면 task 가 검증 불가능해진다.

| 대상 | 검증 작업 |
|---|---|
| 파서·정규화 | 픽스처 기반 pytest 작성 및 통과 |
| 크롤링 실행 | 실사이트 1회 실행 후 `crawl_runs` 행과 카운트 확인 |
| 스케줄러 | 짧은 주기로 등록해 2회 실행되는지 확인 후 원복 |
| 화면 | 로컬에서 해당 화면 열고 HTMX 동작 확인 |
| 스키마 | 마이그레이션 적용·역적용 확인 |

## 출력 형식

```markdown
# Tasks: <PRD명> - <단위 N>

> PRD: `.claude/tasks/todo/<prd-파일명>.md`
> 범위: <요약>
> 상태: 진행 중

### 관련 파일

- `app/crawler/fetcher.py` - 공용 fetch 클라이언트

## 작업

- [ ] 1.0 상위 작업 (배포 단위)
    - [ ] 1.1 하위 작업 (커밋 단위)
        - [ ] 1.1.V 검증: <위 표의 해당 항목>
    - [ ] 1.2 하위 작업 (커밋 단위)
        - [ ] 1.2.V 검증: <해당 항목>
```

## 규칙

- 확인 없이 분석부터 파일 저장까지 자동 완료한다
- 반드시 단위별로 파일을 나눈다. 단일 파일 금지
- 상태 표시는 체크박스와 단어만 쓴다. 이모지·아이콘 금지 (`rules/writing.md`)
- 완료 후 생성 파일 목록만 간단히 보고한다
