# PRD 기반 작업 목록 생성

PRD 를 **배포 단위 파일 분리** + **커밋 단위 하위 작업** 구조로 분해한다.

## 폴더 구조

```
.claude/tasks/
├── todo/                       PRD 및 신규 task 파일
│   ├── prd-*.md
│   ├── tasks-<prd명>-push1.md
│   └── tasks-<prd명>-push2.md
└── done/                       완료된 작업 아카이브 (task-cleaner 가 관리)
    └── <기능명>/
        ├── tasks-<prd명>-push1.md
        └── result-<prd명>-push1.md
```

`todo/`, `done/` 이 없으면 자동 생성한다.

## 생성 프로세스 (확인 없이 자동 완료)

### 1. PRD 분석

인자로 받은 파일을 읽는다. 없으면 `.claude/tasks/todo/` 에서 최신 `prd-*.md` 를 찾는다.
기능 요구사항 전체를 파악하고, PRD 의 **비목표와 미결정 사항을 먼저 확인한다.**

비목표는 작업으로 만들지 않는다. 미결정 사항에 걸린 작업은 만들되 "결정 필요" 로 표시하고
그 결정 없이 시작하지 못한다는 것을 작업 항목에 적는다.

### 2. Push 단위 파일 분리

각 Push = **별도 파일** (`.claude/tasks/todo/tasks-<prd명>-push<N>.md`):
- 독립 배포 가능한 기능 단위
- 하위 커밋 3~7개

**이 서비스에서는 파이프라인 단계가 곧 배포 단위다.**

| Push | 범위 |
|---|---|
| 기반 | 스키마, 마이그레이션, 설정, 공용 fetch 클라이언트 |
| 셀렉터 생성 | HTML 정제, LLM 호출, 스키마 검증 |
| 크롤링 실행 | 파서, 재시도, 1회 실행과 `crawl_runs` 기록 |
| 워크플로우 | 승격, APScheduler 등록, 동시성 상한, 실패 임계치 |
| 정규화 | 규칙 엔진, 규칙 CRUD |
| 화면 | 등록·테스트·워크플로우·데이터 조회 |
| 제공 API | 커서 기반 조회, `delivered_at` |

한 파일이 두 단계를 걸치면 잘못 나눈 것이다. 순서도 위 표가 대체로 맞다 — 스키마가 없으면
아무것도 저장할 수 없고, 1회 실행이 안 되면 스케줄링할 것이 없다.

### 3. 커밋 단위 하위 작업

각 하위 작업 = **하나의 Git 커밋**:
- 파일 수정 5개 미만
- 독립 검증 가능

### 4. 검증 작업 자동 추가

모든 구현 작업 뒤에 검증 작업을 붙인다. **대상에 따라 다른 검증을 쓴다.**
이걸 "테스트 작성" 으로 뭉뚱그리면 검증 불가능한 task 가 된다.

| 대상 | 검증 작업 |
|---|---|
| 파서·정규화 | `tests/fixtures/` 픽스처 기반 pytest 작성 및 통과 |
| 셀렉터 생성 | 저장된 HTML 로 생성 호출, 필드별 매칭 개수 확인 |
| 크롤링 실행 | 실사이트 1회 실행 후 `crawl_runs` 행과 카운트 확인 |
| 스케줄러 | 짧은 주기로 등록해 2회 실행 확인 후 원복 |
| 화면 | 로컬에서 해당 화면 열고 HTMX 동작 확인 |
| 스키마 | 마이그레이션 적용·역적용 확인 |
| 제공 API | 커서로 두 번 조회해 누락·중복 없는지 확인 |

실사이트를 때리는 검증은 push 당 최소 횟수로 잡는다. 하위 작업마다 실행하지 않는다
(`.claude/rules/crawling.md`).

## 출력 형식 (Push 파일)

```markdown
# Tasks: <PRD명> - Push <N>

> PRD: `.claude/tasks/todo/<prd-파일명>.md`
> Push 범위: <기능 요약>
> 상태: 진행 중

## 관련 파일

- `app/crawler/fetcher.py` - 공용 fetch 클라이언트
- `tests/fixtures/` - 파서 테스트용 저장 HTML

## 선행 조건

- Push <N-1> 완료 (또는 없음)
- 결정 필요: <PRD 미결정 사항 중 이 Push 를 막는 것>

## 작업

- [ ] 1.0 상위 작업 (Push 범위)
    - [ ] 1.1 하위 작업 (커밋 단위)
        - [ ] 1.1.V 검증: <위 표의 해당 항목>
    - [ ] 1.2 하위 작업 (커밋 단위)
        - [ ] 1.2.V 검증: <해당 항목>
```

## 규칙

- 사용자 확인 없이 분석 → 파일 저장까지 자동 완료한다
- 반드시 Push 단위로 파일을 나눈다. 단일 파일 금지
- PRD 의 비목표를 작업으로 만들지 않는다 (`.claude/rules/core.md`)
- 검증 작업은 위 표에서 고른다. "테스트 작성" 만 쓰지 않는다
- 상태·진행 표시는 체크박스 `- [ ]` / `- [x]` 와 단어(`진행 중`·`완료`)만 쓴다.
  이모지·아이콘은 넣지 않는다 (`.claude/rules/writing.md`)
- 완료 후 생성된 파일 목록만 간단히 보고한다
