# 롯데그룹 (recruit.lotte.co.kr)

- 리스트 URL: https://recruit.lotte.co.kr/apply/announcement
- 상세 URL 패턴: `/apply/announcement/detail/<번호>`. 목록 항목의 `href` 를 그대로 따라간다
- 수집 방식: 목록·상세 둘 다 `static`. 여섯 사이트 중 유일하게 API 를 쓰지 않는다
- 페이지네이션: 없다. 정적 한 장에 8건이 다 들어 있다 (2026-08-25 확인)
- 날짜 포맷: `2026.08.20 ~ 2026.08.31` 인 기간이다. `deadline` 규칙이 `~` 앞을 떼고
  `%Y.%m.%d` 로 읽는다
- robots.txt: 공용 fetch 클라이언트의 robots 확인을 통과했다
- 권장 주기: 30분으로 등록돼 있다 (workflow 2)

## 자격요건은 본문 안에 있고 제목으로 찾는다

상세에 자격요건만 담은 요소가 따로 없다. `응시자격` 이라는 제목 다음에 오는 목록이 그것이라,
셀렉터가 제목의 글자를 보고 그다음 형제를 잡는다 (`:-soup-contains`, soupsieve 확장).

**`n번째 ul` 로 잡지 않는다.** 상세마다 절 개수가 다르고, 절 하나가 늘거나 줄면 엉뚱한 값이
자격요건으로 들어온다. 2026-08-25 픽스처의 절은 응시자격·모집부문·채용조건·지원서 접수·
전형절차·기타사항·문의처 일곱 개였고 그중 `자격` 이 들어간 제목은 하나뿐이다.

같은 판정을 `tests/test_lotte_selectors.py` 가 저장된 상세 픽스처로 돌려 본다.

직무별 상세 자격요건은 본문 안 표의 한 열에 있다. 열은 CSS 로 지목할 수 없어 뽑지 않는다 —
표 전체가 `body` 안에는 들어 있다.

## 목록의 링크에 쿼리가 두 번 붙는다

항목의 `href` 가 `.../detail/21931077?compcd=?id=bookmark1000` 이다. `?` 가 두 번 들어간
사이트 쪽 표기이고, 그대로 따라가면 상세가 정상으로 열린다. 그래서 손대지 않았다.

`raw_jobs.source_url` 에 이 주소가 그대로 들어가므로 소비 측 링크에도 같은 꼬리가 붙는다.
보기 싫다는 이유로 셀렉터에서 자르지 않는다 — 자르면 셀렉터가 사이트 구조가 아니라 그 사이트의
문자열에 묶인다.
