# 한화 (www.hanwhain.com)

- 리스트 URL: https://www.hanwhain.com/portal/apply/recruit
- 상세 URL 패턴: `/portal/apply/recruit/detail?rtSeq=<공고번호>` (브라우저 주소창에서 확인한 것이고,
  목록 DOM 에서 뽑아낸 것이 아니다)
- 렌더링: Playwright 필요. 근거는 리스트 URL 의 정적 응답이 2,489자이고 그중 본문이 3자,
  반복 항목 0개라는 것이다. 렌더 후에는 441,363자에 `.recruit-list > li` 가 20건 잡힌다
- 페이지네이션: 확인하지 않았다
- 날짜 포맷: `2026.08.13 16:00 ~ 2026.08.23 23:59` (시작과 마감이 한 문자열에 있다).
  정규화 규칙은 아직 없다
- robots.txt: 공용 fetch 클라이언트의 robots 확인을 통과했다
- 권장 주기: 등록하지 못했으므로 정하지 않았다

## 지금은 등록할 수 없다

목록 항목 안에 `a` 태그가 하나도 없다. 20개 항목 전부에서 0개다. 상세로 가는 이동이 Vue
라우터이고, `rtSeq` 는 렌더된 DOM 어디에도 문자열로 남지 않는다.

`list.link` 는 잡은 노드의 `href` 를 읽는다. `href` 가 없으면 링크가 없는 것이고, 링크가 없는
항목은 파서가 버린다. 그래서 목록은 20건 다 잡히는데 실행은 실패한다.

2026-08-22 실행(run 3) 결과: `status=failed`, `error_class=parse`, 사유
`item 20건을 잡았지만 어느 항목에서도 title, link 를 읽지 못했다`. 이 사이트에서 title 은
20/20 으로 잘 읽힌다 — 사유가 필수 필드 이름을 통째로 적고 있었던 것이고, 그 뒤 못 읽은
필드만 적도록 고쳤다. 같은 실행을 지금 돌리면 `link` 만 적힌다.

## 속성 + URL 템플릿으로도 풀리지 않는다

Push 14 가 넣은 두 번째 링크 방식은 항목의 속성값으로 상세 URL 을 만든다. 이 사이트에는 끼울
속성값이 없다.

2026-08-22 에 렌더한 목록(442,933자)에서 확인한 것이다.

| 확인한 것 | 결과 |
|---|---|
| 문자열 `rtSeq` 가 페이지 전체에 나오는 횟수 | 0 |
| 항목 `li` 가 가진 속성 | `data-v-c0fc20d4` 하나뿐. Vue 의 스코프 표시라 공고와 무관하다 |
| 항목 안의 `a` 개수 | 0 |

공고 번호가 DOM 에 아예 없으므로 템플릿에 끼울 값이 없다. 넓힌 셀렉터로 비슷한 값을 잡아
URL 을 만드는 것은 없는 번호를 지어내는 것이고, 그렇게 만든 URL 은 다른 공고를 가리킨다.

다음에 이 사이트를 다시 볼 사람에게: 여기서 셀렉터를 더 손보지 말고, 목록을 채우는 XHR
응답에 `rtSeq` 가 있는지부터 본다. 있다면 그것은 셀렉터 문제가 아니라 API 를 직접 읽는
별개의 수집 방식이고, 새 작업으로 판단할 일이다.

## 셀렉터 특이사항

생성 모델이 `list.link` 로 `h4.recruit-title` 을 골랐고 자체 검증은 20/20 으로 통과시켰다.
검증이 노드 수만 세고 `href` 가 있는지는 보지 않았기 때문이다. 그 판정은 Push 14 에서 고쳤다 —
지금 같은 셀렉터를 넣으면 `list.link` 가 0건으로 실패하고, 사유에 `href` 가 없다고 적힌다.

회사명은 항목마다 다르다. `.affiliate-name` 에 계열사 이름이 들어 있고 20/20 으로 잡힌다.
`crawlers.default_company` 를 쓸 사이트가 아니다.

## 2026-08-24: 풀렸다. 위의 "불가능" 판정은 더 이상 맞지 않는다

두 가지 길이 다 된다.

### 1. 목록 API (권장)

```
POST https://hwadm.hanwhain.com/new-backend/portal/api/rcRecruit/search-rcrt
  content-type: application/json
  referer: https://www.hanwhain.com/
  body {"langCd":"ko","searchText":"","sdSeqList":null,"rtNrcrtYn":"","rtCarrYn":""}
```

브라우저 없이 `curl` 로 200, 5,383바이트, `data.list` 에 20건이다. 항목마다 이렇게 들어 있다.

| 키 | 뜻 | 예 |
|---|---|---|
| `rtSeq` | 공고 번호. 상세 URL 에 끼운다 | `19463` |
| `rtNm` | 제목 | `LIFEPLUS부문 'LIFEPLUS TV 마케팅 기획 및 운영` |
| `sdNm` | 계열사 | `한화생명` |
| `rtAcptStrtDttm` / `rtAcptEndDttm` | 접수 시작·마감 | `2026.08.12 08:00` / `2026.08.25 15:00` |

계열사 11곳이 확인됐다 — (주)한화 글로벌부문, (주)한화 전략부문, 한화모멘텀, 한화생명,
한화솔루션/큐셀, 한화에어로스페이스, 한화엔진, 한화오션, 한화오션에코텍, 한화첨단소재,
한화투자증권.

위에서 "렌더된 DOM 어디에도 `rtSeq` 가 문자열로 남지 않는다" 고 적은 것은 사실이다. DOM 이
아니라 **그 DOM 을 채운 응답**에 있었다. 목록 HTML 만 본 것이 그때의 한계였다.

`hwadm.hanwhain.com` 은 별도 호스트다. 공용 fetch 클라이언트가 호스트별로 robots 와 딜레이를
따로 잡으므로 그 경로로 나가면 된다.

**robots.txt 가 없다.** `www.hanwhain.com/robots.txt` 와 `hwadm.hanwhain.com/robots.txt` 가
둘 다 200 을 주지만 내용은 SPA 셸 HTML 이다. 지시가 적힌 robots 파일이 아니므로 제한이
명시되지 않은 상태이고, 그렇다고 넉넉히 다녀도 된다는 뜻은 아니다. 딜레이는 그대로 지킨다.

### 2. 항목 클릭

항목에 `a` 가 없어도 클릭하면 이동한다. Vue 라우터가 클릭을 받아 주소를 바꾸고, 이동한 뒤
`page.url` 을 읽으면 상세 주소를 알 수 있다.

2026-08-24 측정: 목록 로드 4.51초, 항목 20건, 앞 5개 항목의 `a` 개수 전부 0.
클릭 3건 모두 이동했고 걸린 시간은 항목당 1.25~1.27초다.

```
[0] 1.27초  https://www.hanwhain.com/portal/apply/recruit/detail?rtSeq=19463
[1] 1.25초  https://www.hanwhain.com/portal/apply/recruit/detail?rtSeq=19483
[2] 1.26초  https://www.hanwhain.com/portal/apply/recruit/detail?rtSeq=19482
```

주소 형식이 위에 적어 둔 `?rtSeq=` 패턴과 같다.

클릭은 API 를 찾지 못한 사이트에서도 통하는 일반적인 방법이지만, 항목마다 이동과 복귀가 필요해
API 보다 느리다. **API 가 있으면 API 를 쓴다.**
