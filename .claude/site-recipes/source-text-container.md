# 상세 원문 컨테이너 측정 (2026-08-28)

`raw_jobs.raw_data_json.source_text` 에 넣을 상세 원문을 무엇으로 잡을지 정하려고 열한 사이트의
저장된 상세 픽스처에 두 방법을 다 돌린 기록이다. 사이트 하나의 레시피가 아니라 열한 곳을 가로로
잰 것이라 도메인 파일을 두지 않고 여기 모았다.

- 대상: `tests/fixtures/` 의 상세 픽스처 열한 개 (HTML 일곱, JSON 넷)
- 본문 셀렉터: `seeds/site-configs-20260826.json` 의 `detail.body` 를 그대로 썼다
- 글자 수는 `app/crawler/parser.py` 의 `field_text()` 와 같은 방식(블록 태그 경계에 줄바꿈)으로
  뽑은 텍스트 길이다
- 잰 사람이 판정한 것은 "본문 밖에서 들어온 글자가 무엇인가" 하나다. 후보에서 본문 노드를 지운
  나머지 텍스트를 그대로 읽고 적었다

API 상세에는 조상 요소가 없다. 대응되는 것은 응답 전체이거나 본문 경로의 부모 객체다.

| 사이트 | 응답 값 전체 | 뽑은 본문 | 응답이 함께 담은 것 |
|---|---|---|---|
| LG | 164,731 | 38,019 | `data.interestJobNoticesList` 에 다른 공고 목록. 본문 경로의 부모 `recList` 만 해도 129,369자 |
| 삼성 | 17,081 | 3,277 | `data.items` 에 모집 부문별 항목 |
| 한화 | 1,671 | 948 | 지원 자격 코드값 등 |

네 곳 중 셋은 본문이 경로 여러 개를 이어 만든 값이라 부모 객체가 하나로 정해지지도 않는다
(한화 `data.item.unitDt.*.ruNm` 외 둘, 삼성 셋, 현대자동차 셋).

## 고른 방법

**B. 본문 셀렉터가 잡은 노드의 조상 1단계.** 그 노드에서 페이지 부속(`header`, `nav`, `footer`,
`aside` 태그와 `aside`·`footer`·`gnb` 가 들어간 클래스)만 뺀다. 별도 셀렉터는 두지 않는다.

근거는 넷이다.

조상 1단계는 일곱 곳 중 넷에서 이 공고의 이름표 값(회사·마감·근무지·경력)만 원문에 넣었다.
두산과 토스는 본문이 이미 그것을 담고 있어 늘어난 글자가 0자였다. 다른 공고가 함께 들어온
것은 카카오 한 곳뿐이고, 그것은 아래의 부속 제거가 걷어낸다.

조상을 2·3단계로 올리면 그때부터 다른 화면이 섞인다. 네이버 조상3은 목록 화면의 필터와 다른
공고 카드로 3,880자에서 6,797자가 됐다. 그러고도 늘어나는 것은 롯데그룹의 빵부스러기·인쇄
버튼 155자 같은 것뿐이라, 올릴 이유가 없다.

별도 셀렉터는 최선일 때도 네이버·토스·카카오에서 조상 1단계와 같은 노드였고 SK 는 4자 차이였다.
남는 세 곳에서 더 담은 것은 롯데그룹의 빵부스러기 155자, 두산의 빵부스러기 21자, 그리고
우아한형제들의 다른 공고 여덟 건 528자다. 사람이 고른 `section.wrap-detail` 이 다른 공고를
통째로 끌고 들어왔다는 것이 이 방법의 값이다. 컨테이너를 사람이 고르는 일 자체가 오염이
들어오는 자리이고, 사이트마다 판단이 하나씩 늘어나는 값을 치르고 얻는 것이 없다.

부속 제거는 열한 픽스처에서 딱 한 번 걸렸다. 카카오의 `div.aside_board` 469자이고, 그것이
조상 1단계에 남는 유일한 다른 공고 목록이다. 나머지 여섯 곳은 제거 전후 글자 수가 같다.
`tests/fixtures/pythonorg-job-detail-20260821.html` 과 토스 두 번째 픽스처에서도 걸리지 않았다.

부모가 `body` 나 `html` 이면 본문 노드를 그대로 쓴다. 페이지 전체가 원문이 되는 것을 막는
안전장치이고, 잰 일곱 곳에서는 부모가 전부 `div` 라 이 경우가 없었다.

API 상세는 원문을 뽑지 않는다. 응답 전체는 LG `interestJobNoticesList` 처럼 다른 공고를 담고,
본문 경로의 부모 객체도 LG 에서 129,369자다. 원문이 없는 건은 분류가 본문으로 떨어진다
(`.claude/tasks/todo/prd-side-workflows.md` 4절). 네 곳의 본문은 상세 문서의 내용을 이미 그대로
담고 있어 잃는 것이 적다.
