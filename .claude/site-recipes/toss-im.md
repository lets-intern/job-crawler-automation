# 토스 (toss.im)

- 리스트 URL: https://toss.im/career/jobs
- 수집 방식: 목록은 `playwright`, 상세는 `static` (크롤러 33, 2026-08-25 등록)
- 상세 URL 형식: `https://toss.im/career/job-detail?job_id=<번호>` (목록 항목의 `href` 그대로)
- 페이지네이션: 없다. 렌더하면 한 화면에 263건이 다 들어 있다 (2026-08-25 측정)
- 날짜 포맷: 목록에 날짜가 없다. `list.date` 는 빈 채로 저장돼 있고, 마감일은 상세에서 온다
- robots.txt: 공용 fetch 클라이언트의 robots 확인을 통과했다
- 권장 주기: **승격 전에 아래 `detail.body` 를 손보정한다**

## 목록 API 는 없다

작업 지시에 적혀 있던 `api-public.toss.im/.../workspaces/13/posts` 는 공고 목록이 아니라
커리어 아티클 목록이다(제목이 "토스뱅크 Server Chapter와 Server Platform Team이 일하는 방식"
같은 글 제목이다). 2026-08-25 에 목록 페이지를 렌더하며 관찰한 JSON 응답은 푸터·배너·헤더
셋뿐이고 공고 배열을 담은 것이 없었다. 공고 263건은 초기 HTML 안에 `href="/career/job-detail?job_id=..."`
로 이미 들어 있다.

그래서 목록은 렌더로 남는다. 그 세 응답은 "후보가 없는 응답" 픽스처로 남겨 뒀다
(`tests/fixtures/toss-*-20260825.json`).

## 상세 페이지 모양이 공고마다 다르다

**이 사이트의 함정이다.** 일반 공고와 "집중 채용" 랜딩 페이지가 같은 `job-detail` 주소를
쓰는데 마크업이 다르다. 2026-08-25 측정에서 `job_id=5853067003` 에는 `h1` 이 있고
`job_id=7827417003` 에는 없다.

본문을 담은 요소를 구분하는 유일한 표시가 자동 생성 클래스다. 페이지 안에
`div.p-container__inner` 가 둘인데 앞의 것이 네비게이션(37자), 뒤의 것이 공고 본문이고,
둘을 가르는 것은 부모의 `css-6bhaou` 뿐이다.

| 저장된 값 | 결과 |
|---|---|
| `div.css-1d3w5wq` (크롤러 26) | 세 건 중 한 건만 본문을 읽었다. 나머지는 `parse` 실패 |
| `.p-container__inner` (크롤러 33) | 세 건 다 성공으로 끝났지만 본문이 네비게이션 37자다 |

두 번째가 더 위험하다. 실패로 보이지 않으면서 값이 틀린다.

손보정할 값은 이것이다. 2026-08-25 에 두 공고에서 확인했다.

```
.p-container.css-6bhaou .p-container__inner
```

자동 생성 클래스에 기대는 자리이므로 토스가 배포하면 여기가 먼저 깨진다. 깨지면 본문이
0건으로 떨어져 `parse` 실패로 드러난다.
